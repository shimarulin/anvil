# Rule: Markdown File Output Format

When outputting Markdown project files, follow ALL of these rules:

## 1. Structure per file

### `path/to/file.ext`

Optional description or notes.

<!-- file: path/to/file.ext -->
```lang
content
```

- The Markdown heading (`### \`path\``) makes output human-readable.
- The HTML marker (`<!-- file: path -->`) on the line **immediately before** the
  opening fence enables automated extraction. Never omit it for project files.
- Code blocks **without** the `<!-- file: -->` marker are treated as illustrative
  snippets and will be ignored by the extractor.

## 2. Markdown file content (or any content containing triple backticks)

When the file itself contains triple backticks (e.g. `.md` files with fenced
code blocks), wrap the entire block in **quadruple** backticks so the inner
fences render correctly:

### `docs/README.md`

<!-- file: docs/README.md -->
````markdown
# Title

Some text

```bash
echo "hello"
```
````

## 3. Multiple files

Output files sequentially, each with its own heading and marker:

### `src/main.py`

Entry point.

<!-- file: src/main.py -->
```python
print("hello")
```

### `src/utils.py`

<!-- file: src/utils.py -->
```python
def helper():
    pass
```

## 4. Summary

| Element | Required? | Purpose |
|---|---|---|
| `### \`path\`` heading | Yes | Human readability, navigation |
| `<!-- file: path -->` marker | Yes | Automated file extraction |
| Language tag on fence | Yes | Syntax highlighting |
| Description between heading and code | Optional | Context for the reader |
| Quadruple backticks | Only when content contains triple backticks | Correct rendering |
```
