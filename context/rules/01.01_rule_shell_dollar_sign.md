# Rule: `$` in shell scripts vs Makefiles

## Problem

When outputting `.sh` / `.bash` files, the AI sometimes writes `$$` instead of `$`,
contaminating shell scripts with Makefile escape syntax.

- In **Makefile**: `$$` → literal `$` passed to shell (correct)
- In **shell scripts**: `$$` → PID of current process (almost always a bug)

## Rule

1. **Determine the file type from the `<!-- file: -->` marker or heading**, not from
   surrounding context.

2. **Shell scripts** (`.sh`, `.bash`, `.zsh`, or shebang `#!/usr/bin/env bash`):
   - Always use single `$` for variables: `$HOME`, `$1`, `${var}`
   - `$$` is valid ONLY when you intentionally need the shell PID (rare)

3. **Makefiles** (`Makefile`, `*.mk`):
   - Use `$$` to pass a literal `$` to the shell: `$$HOME`, `$$1`, `$$(cmd)`
   - Use single `$` only for Make variables: `$(MAKE)`, `$@`, `$<`

4. **Before writing any `$` sign**, check: _"Am I inside a Makefile or a shell script?"_

## Quick reference

| Context    | Want shell `$HOME` | Want Make var `$(CC)` | Want shell PID |
|------------|---------------------|-----------------------|----------------|
| `.sh` file | `$HOME`             | N/A                   | `$$`           |
| `Makefile` | `$$HOME`            | `$(CC)`               | `$$$$`         |

## Examples

### Correct `.sh`

```bash
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
echo "$HOME/.config"
```

### Correct `Makefile`

```makefile
install:
	@echo "$$HOME/.config"
	@SCRIPT_DIR="$$(cd "$$(dirname "$${BASH_SOURCE[0]}")" && pwd)"
```

### WRONG — shell script with Makefile escaping

```bash
# ❌ BUG: $$ in .sh means PID, not literal $
SCRIPT_DIR="$$(cd "$$(dirname "${BASH_SOURCE[0]}")" && pwd)"
```
