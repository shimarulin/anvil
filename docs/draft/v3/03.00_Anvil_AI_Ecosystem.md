# Anvil — AI Ecosystem

The AI layer is a first-class subsystem in Anvil, designed to replace GitHub Copilot, Cline, and Claude Code with open-source alternatives using any OpenAI-compatible provider.

## Tool Selection Guide

| Task                              | Tool                      | Why                                     |
|-----------------------------------|---------------------------|-----------------------------------------|
| Quick question about code         | CodeCompanion chat        | Fast, integrated, buffer context        |
| Fix diagnostics / errors          | CodeCompanion /fix        | Sees LSP diagnostics directly           |
| Explain error under cursor        | wtf.nvim                  | One keypress, instant popup             |
| Code review                       | CodeCompanion /review     | Full file + diagnostics                 |
| Generate tests                    | CodeCompanion /gentest    | Understands project test patterns       |
| Inline completion                 | minuet-ai (F2 toggle)    | Non-intrusive, opt-in                   |
| Multi-file refactoring            | Aider                     | Best at editing multiple files          |
| Complex feature with planning     | OpenCode                  | Built-in planner + sub-agents           |
| Explore unfamiliar codebase       | CodeCompanion + MCP       | MCP reads files, fetches docs           |
| Database queries / schema         | CodeCompanion + MCP       | postgres MCP server                     |
| Read external documentation       | CodeCompanion /url        | Fetches and converts to text            |
| Switch AI for different project   | :AnvilPreset              | Instant provider/model switch           |

## Provider System

### Concepts

```text
┌─────────────────────────────────────────────────────────┐
│  PROVIDER = endpoint + credentials                      │
│  ├── openrouter (https://openrouter.ai/api/v1)         │
│  ├── ollama    (http://localhost:11434/v1)              │
│  └── corporate (https://llm.corp.internal/v1)          │
├─────────────────────────────────────────────────────────┤
│  MODEL = specific model on a provider                   │
│  ├── openrouter/claude-sonnet (anthropic/claude-sonnet-4)│
│  ├── openrouter/claude-haiku  (anthropic/claude-haiku)  │
│  ├── ollama/qwen-coder        (qwen2.5-coder:14b)      │
│  └── corporate/internal-llm   (corp-llm-v2)            │
├─────────────────────────────────────────────────────────┤
│  SLOT = interaction type → model assignment             │
│  ├── chat      (general conversations)                  │
│  ├── inline    (code completions, minuet-ai)            │
│  ├── agent     (autonomous agents)                      │
│  ├── architect (planning, large context)                │
│  ├── fast      (quick tasks, commit msgs)               │
│  └── local     (privacy-sensitive, always local)        │
├─────────────────────────────────────────────────────────┤
│  PRESET = named set of slot→model assignments           │
│  ├── default    (cloud + local)                         │
│  ├── corporate  (private provider only)                 │
│  └── local-only (Ollama only)                           │
└─────────────────────────────────────────────────────────┘
```

### Resolution Order

When an AI tool needs credentials for a slot:

1. **Session override** — temporary, set via `:AnvilSlot chat <model>` with "session only"
2. **Active preset** — the currently selected preset's slot assignment
3. **Fallback** — if slot is not configured, falls back to the `chat` slot

### Commands

| Command                          | Description                       |
|----------------------------------|-----------------------------------|
| `:AnvilPreset`                   | Interactive preset picker         |
| `:AnvilPreset <name>`            | Switch to named preset            |
| `:AnvilSlot`                     | Interactive slot + model picker   |
| `:AnvilSlot <slot>`              | Pick model for a specific slot    |
| `:AnvilSlot <slot> <model>`      | Set slot to model directly        |
| `:AnvilSavePreset`               | Save current config as new preset |
| `:AnvilProviderConfig`           | Show current configuration        |
| `:AnvilProviderEdit`             | Open config file in editor        |

### Keymaps

| Key             | Action              |
|-----------------|---------------------|
| `<leader>aPp`   | Switch preset       |
| `<leader>aPs`   | Change slot model   |
| `<leader>aPn`   | Save as new preset  |
| `<leader>aPc`   | Show config         |
| `<leader>aPe`   | Edit config file    |

### Preset Scenarios

- **Corporate project** (closed network): `:AnvilPreset corporate` → All slots use `corporate/internal-llm` → No data leaves the corporate network → Local slot still uses Ollama for offline work
- **Standard development**: `:AnvilPreset default` → Chat/agents use Claude Sonnet (cloud) → Inline completions use Claude Haiku (fast, cheap) → Local slot uses Ollama
- **Open-source project** (sponsored): `:AnvilPreset opensource` → All slots use the sponsor's provider → Custom preset saved with `:AnvilSavePreset`
- **Quick model swap for one task**: `:AnvilSlot architect openrouter/claude-sonnet` → Only architect mode changes (session override) → Other slots unchanged → Not persisted — reverts on restart

## Context Gathering

`lua/anvil/ai/context.lua` — collects:

- Buffer diagnostics
- Project-wide errors
- Test results from neotest
- Treesitter context (current function/class)
- Git diff
- Project structure and key files (cached)
- Language-specific AI context from lang packs

Available via slash commands: `/project`, `/diagnostics`, `/tests`, `/diff`, `/url`

## CodeCompanion Configuration

`lua/anvil/ai/agents.lua` builds CodeCompanion adapters dynamically from the slot system:

```lua
-- Each adapter is a function that resolves the slot at call time
adapters = {
  chat      = make_adapter("chat"),
  fast      = make_adapter("fast"),
  architect = make_adapter("architect"),
  agent     = make_adapter("agent"),
  ["local"] = make_adapter("local"),
},
```

When you switch presets or change a slot, the next CodeCompanion request will use the new model automatically.

## Inline Completion

`lua/anvil/ai/completion.lua` — uses the `inline` slot:

- Disabled by default
- Toggle with `<F2>`
- Uses the model assigned to the `inline` slot in the active preset
- Switching presets automatically changes the inline completion model

## External Tools

`lua/anvil/ai/tools.lua` — Aider and OpenCode use the `agent` slot for credentials:

```lua
-- Aider receives model/endpoint/key from the "agent" slot
M.build_aider_cmd = function()
  local providers = require("anvil.ai.providers")
  return {
    "aider",
    "--model", providers.model_for("agent"),
    "--openai-api-base", providers.endpoint_for("agent"),
    "--openai-api-key", providers.api_key_for("agent"),
    ...
  }
end
```

Switching presets changes which provider Aider uses.

## Health Check

`:checkhealth anvil_ai` verifies:

- Provider system loaded
- Active preset and all slot assignments
- API key status for each slot's provider
- Config file existence
- Plugin availability (CodeCompanion, minuet-ai, MCPHub, wtf.nvim, toggleterm)
- External tools (aider, opencode)
- Utilities (pandoc, curl, node, npm)
- MCP server configuration
