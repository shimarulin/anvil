# Anvil — Voice Layer

Voice input subsystem: speech-to-text, command recognition, AI-powered interpretation, and hands-free editor control. Disabled by default — activates on demand via `<F3>` (push-to-talk) or `<leader>vv` (toggle continuous listening).

## Design Decisions

**Variant C — AI-powered interpretation** (ADR-030). Instead of building a rigid grammar parser, voice commands flow through two stages: (1) direct phrase matching against a command registry, and (2) AI fallback via the `fast` slot for anything unmatched. This leverages Anvil's existing AI infrastructure to understand natural language, tolerate STT errors, and handle synonyms without maintaining complex grammars.

**whisper.cpp as default STT engine.** Runs locally, supports 99 languages, no cloud dependency. The `small` model (244 MB) provides the best balance of accuracy and speed for short voice commands on CPU. Larger models (`turbo`, `large-v3`) available for users with GPU or higher accuracy needs.

**Multi-language support.** Whisper auto-detects the spoken language. Users can fix a language via configuration for faster recognition. Commands are registered with phrases in multiple languages — the system matches against all of them.

**External process via libuv.** The STT engine runs as a separate process communicating via stdout pipe. This never blocks Neovim's main loop. Managed through `vim.uv` (libuv), consistent with how Anvil handles other external tools.

**Off by default** (same pattern as minuet-ai, ADR-022). Voice input is entirely opt-in. No microphone access, no background process until the user explicitly activates it.

**Provider-style engine abstraction.** The STT engine uses a strategy pattern (like `ui/strategies/`), allowing future backends (Vosk for ultra-low-latency, cloud STT for maximum accuracy) without changing the command layer.

## How It Works

### Recognition Pipeline

```text
Microphone
    │
    ▼
whisper.cpp (stream mode)
    │  stdout: recognized text lines
    ▼
engine.lua — parse, detect language, schedule on main loop
    │
    ▼
voice/init.lua — on_recognized(text, lang, confidence)
    │
    ├──▶ commands.lua — try_match()
    │    Fuzzy match against registered phrases
    │    Score ≥ 0.7 → execute action directly
    │    │
    │    └──▶ Action executed ✓
    │
    └──▶ (no match)
         │
         ▼
         interpreter.lua — interpret()
         Send to AI (slot: fast):
           system prompt with action schema
           + recognized text
           + current file context
         │
         ▼
         AI returns JSON: {"action": "find_file", "query": "main"}
         │
         ▼
         Execute mapped action ✓
```

### Two-Stage Command Resolution

**Stage 1 — Direct matching.** The command registry holds phrases in multiple languages. Fuzzy string similarity (word overlap + substring matching) tolerates minor STT errors. This stage is instant — no network call.

**Stage 2 — AI interpretation.** When no direct match is found, the recognized text is sent to the AI provider configured for the `fast` slot. A structured system prompt constrains the AI to respond with a JSON action object from a predefined schema. The AI understands context (current file, filetype), synonyms, and partial commands.

This two-stage approach means:
- Common commands execute instantly (no AI latency)
- Unusual or creative phrasing still works (AI handles it)
- New commands can be added to either stage independently

## Command Registry

### Registration Format

```lua
M.register({
  phrases = {
    en = { "find file", "open file", "search file" },
    ru = { "найди файл", "открой файл", "поиск файла" },
    de = { "datei finden", "datei öffnen" },

  action = function() vim.cmd("Telescope find_files") end,
  category = "navigation",
  desc = "Find file (Telescope)",
})
```

## AI Interpreter (Variant C)

The interpreter sends a structured prompt to the `fast` AI slot:

```text
System: You are a voice command interpreter for Neovim.
        Available actions: { find_file, grep, goto_line, ... }
        Respond with EXACTLY one JSON object.

User:   Voice command (language: ru): "открой файл мейн"
        Current file: src/index.ts
        Filetype: typescript

AI:     {"action": "find_file", "query": "main"}
```

### Action Schema

The AI can return any of these action types:

```text
Navigation:   find_file, grep, goto_definition, find_references,
              goto_line, open_explorer, document_symbols
Buffers:      next_buffer, prev_buffer, close_buffer, switch_buffer
Editing:      undo, redo, save, format, rename, code_action,
              comment, select_function, delete_line, insert_text
AI:           ai_chat, ai_fix, ai_explain, ai_review, ai_tests,
              ai_architect, ai_ask
Git:          lazygit, stage_hunk, diff, blame
Testing:      run_test, run_all_tests, debug_test
Debug:        breakpoint, continue, step_over, step_into
Tasks:        run_task
UI:           zen_mode, diagnostics
Other:        unknown (with description)
```

### Why This Works Better Than Grammar Parsing

| Approach | Rigid grammar | AI interpretation |
|---|---|---|
| "open file main" | ✓ | ✓ |
| "show me the main file" | ✗ | ✓ |
| "where is the entry point" | ✗ | ✓ (context-aware) |
| "строка 42" | ✗ (needs per-language grammar) | ✓ |
| "rename this to processData" | ✗ (needs entity extraction) | ✓ |
| STT error: "find fial" | ✗ | ✓ (AI tolerates typos) |

## STT Engine

### whisper.cpp Integration

The engine manages a `whisper-cpp-stream` process:

```text
┌────────────┐     stdout (text lines)     ┌──────────────┐
│ whisper-cpp │ ──────────────────────────▶ │   Neovim     │
│   stream    │                             │  (vim.uv     │
│             │     spawned via             │   pipe read)  │
│  --model    │     uv.spawn()             │              │
│  --language │                             │              │
│  --vad-thold│                             │              │
└────────────┘                              └──────────────┘
```

### Model Selection Guide

| Model | Size | Accuracy (short commands) | Speed (CPU) | Recommended for |
|---|---|---|---|---|
| `tiny` | 39 MB | Good | Realtime | Low-resource machines |
| `base` | 74 MB | Good+ | Realtime | Quick setup, English-primary |
| **`small`** | **244 MB** | **Very good** | **Realtime** | **Default — best balance** |
| `medium` | 769 MB | Excellent | ~2x slower | High accuracy needs |
| `turbo` | 809 MB | Excellent | ~1.5x slower | GPU available |
| `large-v3` | 1.5 GB | Best | ~3x slower | Maximum accuracy, GPU required |

For voice commands (short phrases, 2-5 words), even the `small` model achieves near-perfect accuracy across supported languages.

### Language Configuration

```lua
-- In voice engine setup (or future config/voice.json):
require("anvil.voice.engine").setup({
  language = "auto",   -- auto-detect (default)
  -- language = "en",  -- English only (faster)
  -- language = "ru",  -- Russian only (faster)
})
```

`auto` mode detects the spoken language per utterance. Fixed language mode skips detection and is ~200ms faster per recognition.

### Audio Recording

For push-to-talk mode, the engine records audio using the first available tool:

| Tool | Platform | Notes |
|---|---|---|
| `arecord` | Linux (ALSA) | Most common on Linux |
| `sox` | Cross-platform | Install via package manager |
| `ffmpeg` | Cross-platform | Uses AVFoundation on macOS |

Continuous listening mode uses `whisper-cpp-stream` which handles audio capture internally via SDL2.

## Installation

### Quick Setup

```bash
# From within Neovim:
:AnvilVoiceInstall small

# This will:
# 1. Clone whisper.cpp
# 2. Build the stream binary
# 3. Download the 'small' model (244 MB)
# 4. Symlink binary to ~/.local/bin/
```

### Manual Setup

```bash
# 1. Build whisper.cpp
git clone --depth 1 https://github.com/ggerganov/whisper.cpp
cd whisper.cpp
make stream

# 2. Download model
./models/download-ggml-model.sh small

# 3. Symlink (optional)
ln -sf $(pwd)/stream ~/.local/bin/whisper-cpp-stream

# 4. Verify
whisper-cpp-stream --model models/ggml-small.bin --language auto
```

### Requirements

| Dependency | Required | Purpose |
|---|---|---|
| whisper.cpp | Yes | Speech-to-text engine |
| ggml model file | Yes | Whisper model weights |
| Audio recorder (arecord/sox/ffmpeg) | For PTT mode | Record audio for push-to-talk |
| SDL2 | For stream mode | Audio capture in continuous mode |
| AI provider (slot: fast) | Recommended | AI command interpretation |

## Integration with Anvil Subsystems

### Event Bus

Voice emits events that any module can subscribe to:

```lua
local events = require("anvil.core.events")

-- React to any recognized speech
events.on("voice:recognized", function(args)
  local text = args.data.text
  local lang = args.data.lang
  -- custom handling
end)

-- React to voice start/stop
events.on("voice:started", function() ... end)
events.on("voice:stopped", function() ... end)
```

### AI Provider System

Voice interpretation uses the existing slot system (ADR-028):

```text
Slot: fast → openrouter/claude-haiku (default)
             Used for: commit messages, error explanations, voice interpretation
```

When the user switches presets (`:AnvilPreset corporate`), voice interpretation automatically uses the corporate provider — no separate configuration needed.

### Language Packs

Voice commands are language-pack-aware. The AI interpreter receives the current filetype, enabling context-sensitive responses:

```text
Voice: "run" (in a Rust file)  → OverseerRun "cargo run"
Voice: "run" (in a Go file)    → OverseerRun "go run ."
Voice: "run" (in a Python file) → OverseerRun "python3 %"
```

```lua
    })

})
```

## Limitations

| Limitation | Workaround |
|---|---|
| No microphone in SSH sessions | Use push-to-talk with local audio forwarding, or disable voice |
| Background noise triggers false positives | Use push-to-talk mode instead of continuous listening |
| whisper.cpp requires ~1-2 GB RAM | Use `tiny` or `base` model on constrained machines |
| SDL2 required for continuous mode | Push-to-talk works without SDL2 (uses arecord/sox/ffmpeg) |
| AI interpretation adds ~0.5-1s latency | Direct command matching is instant; AI is only the fallback |
| Code dictation is experimental | Use AI chat for complex code input instead |
