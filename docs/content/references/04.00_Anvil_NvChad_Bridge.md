# Anvil — NvChad Bridge

The bridge layer connects Anvil's framework-agnostic core to NvChad's specific conventions: `chadrc.lua` configuration, NvChad hook files (`options.lua`, `mappings.lua`, `autocmds.lua`), and the bridge module that handles NvChad-specific boot integration.

## Architecture

```text
lua/
├── chadrc.lua                  # NvChad theme/UI configuration
├── options.lua                 # NvChad options hook (delegates to anvil)
├── mappings.lua                # NvChad mappings hook (delegates to anvil)
├── autocmds.lua                # NvChad autocmds hook (delegates to anvil)
└── anvil/
    └── bridge/
        └── nvchad/
            └── init.lua        # NvChad-specific boot integration
```

## Design Principles

1. **Thin delegation** — NvChad hook files (`options.lua`, `mappings.lua`, `autocmds.lua`) delegate immediately to Anvil core modules. No logic lives in the hooks themselves.
2. **No duplication** — options are defined once in `anvil.core.options`, keymaps once in `anvil.core.keys`, autocmds once in `anvil.core.autocmds`.
3. **NvChad-native where appropriate** — `chadrc.lua` uses NvChad's native format for theme configuration because base46 requires it.
4. **Bridge is optional** — if NvChad is not detected, the bridge module is never loaded. Anvil's boot sequence works without it.

## Files

### `lua/chadrc.lua`

NvChad configuration file. Controls base46 theme, statusline, tabufline, and nvdash.

<!-- file: lua/chadrc.lua -->
```lua
--- NvChad configuration
--- This file is loaded by NvChad's core; it must return M.base46 and M.ui tables.
--- Theme and UI chrome are NvChad-native; everything else delegates to Anvil.
---@type ChadrcConfig
local M = {}

-- ─── Theme (base46) ───
M.base46 = {
  theme = "catppuccin",
  transparency = false,
  hl_override = {
    Comment = { italic = true },
    ["@comment"] = { italic = true },
  },
}

-- ─── UI ───
M.ui = {
  statusline = {
    theme = "default",
    separator_style = "round",
  },
  tabufline = {
    enabled = true,
    lazyload = true,
  },
  nvdash = {
    load_on_startup = true,
    header = {
      "                                   ",
      "   ╔═══════════════════════════╗   ",
      "   ║     ⚒  ANVIL  ⚒          ║   ",

      { txt = "  Find File",    keys = "ff", cmd = "Telescope find_files" },

      { txt = "  Mappings",     keys = "ch", cmd = "NvCheatsheet" },

  },
}

return M
```

### `lua/anvil/bridge/nvchad/init.lua`

NvChad-specific boot integration. Handles anything that requires NvChad APIs.

<!-- file: lua/anvil/bridge/nvchad/init.lua -->
```lua
--- Anvil NvChad bridge
--- Handles NvChad-specific integration that can't be done in framework-agnostic code.
--- This module is only loaded when NvChad is detected.
--- Depends on: NvChad core modules
---@class AnvilBridgeNvChad
local M = {}

--- Apply NvChad-specific settings
--- Called during anvil.boot() when NvChad is detected
function M.apply()
  -- NvChad's base46 handles theme compilation
  -- Ensure theme is compiled on first run
  local base46_ok = pcall(require, "base46")
  if base46_ok then
    -- base46 auto-compiles; nothing to do here
  end

  -- Integrate Anvil events with NvChad
  local events_ok, events = pcall(require, "anvil.core.events")
  if events_ok then
    events.on("ai:preset_changed", function(args)
      -- Update statusline when AI preset changes (if statusline shows AI info)
      vim.cmd("redrawstatus")
    end)
  end

  local logger_ok, logger = pcall(require, "anvil.core.logger")
  if logger_ok then
    logger.debug("NvChad bridge applied")
  end
end

--- Check if NvChad is available
---@return boolean
function M.is_available()
  return pcall(require, "nvchad.ui") and pcall(require, "base46")
end

return M
```
