# Anvil — Bridge Layer

The bridge layer connects Anvil's framework-agnostic core to a specific Neovim framework. The initial (and default) bridge targets **NvChad v2.5+**. The bridge handles bootstrap, framework detection, UI integration, and provides the thin adapter between Anvil's internal APIs and the framework's conventions.

## Design Decisions

- **ADR-001**: NVIM_APPNAME isolation — Anvil coexists with any other Neovim configuration.
- **ADR-023**: NvChad as base framework — minimal core, imperative model, fast startup.
- **ADR-024**: Framework-agnostic core (Path A→C) — explicit boundary between portable and framework-specific code.
- **ADR-025**: Strategy points in editor layer — overridable functions for future multi-framework support.

## Design Principles

1. **Thin delegation** — NvChad hook files (`options.lua`, `mappings.lua`, `autocmds.lua`) delegate immediately to Anvil core modules. No logic lives in the hooks themselves.

2. **No duplication** — options are defined once in `anvil.core.options`, keymaps once in `anvil.core.keys`, autocmds once in `anvil.core.autocmds`.

3. **NvChad-native where appropriate** — `chadrc.lua` uses NvChad's native format for theme and dashboard configuration because base46 and nvdash require it.

4. **Bridge is optional** — if NvChad is not detected, the bridge module is never loaded. Anvil's boot sequence works without it.

## How NvChad Is Installed

NvChad is **not** installed globally or cloned into `~/.config/`. It is loaded as a regular **lazy.nvim plugin** into the Anvil data directory.

Bootstrap Sequence

```text
User runs: NVIM_APPNAME=anvil nvim
│
├── Neovim reads ~/.config/anvil/init.lua
│
├── Step 1: Bootstrap lazy.nvim
│   Is ~/.local/share/anvil/lazy/lazy.nvim present?
│   ├── Yes → skip
│   └── No  → git clone folke/lazy.nvim (stable branch)
│   vim.opt.rtp:prepend(lazypath)
│
├── Step 2: require("lazy").setup(...)
│   ├── NvChad/NvChad (branch v2.5, import = "nvchad.plugins")
│   │   └── lazy.nvim clones into ~/.local/share/anvil/lazy/NvChad/
│   │       Also pulls: NvChad/base46, NvChad/ui, NvChad/menu
│   ├── import = "plugins"
│   │   └── lua/plugins/*.lua (Anvil plugin specs)
│   └── lazy.nvim resolves dependencies, installs everything
│
├── Step 3: require("anvil").boot({...})
│   └── Phase 1-6 (see Core Layer documentation)
│
└── Editor ready
```

## Source Code

### Root `init.lua`

The root `init.lua` is the only file that contains framework-specific bootstrap logic at the top level. Everything else is abstracted behind the bridge.

<!-- file: init.lua -->
```lua
-- ~/.config/anvil/init.lua
-- Anvil: AI-powered forge for Neovim

-- ─── Step 1: Bootstrap lazy.nvim ───
local lazypath = vim.fn.stdpath("data") .. "/lazy/lazy.nvim"
if not vim.uv.fs_stat(lazypath) then
  local out = vim.fn.system({
    "git", "clone",
    "--filter=blob:none",
    "--branch=stable",
    "https://github.com/folke/lazy.nvim.git",
    lazypath,
  })
  if vim.v.shell_error ~= 0 then
    vim.api.nvim_echo({
      { "Failed to clone lazy.nvim:\n", "ErrorMsg" },
      { out,                            "WarningMsg" },
    }, true, {})
    return
  end
end
vim.opt.rtp:prepend(lazypath)

-- ─── Step 2: Load plugins (NvChad + Anvil) ───
require("lazy").setup({
  {
    "NvChad/NvChad",
    lazy = false,
    branch = "v2.5",
    import = "nvchad.plugins",
  },
  { import = "plugins" },  -- lua/plugins/*.lua
}, {
  defaults = { lazy = true },
  install  = { colorscheme = { "nvchad" } },
  ui       = { border = "rounded" },
  performance = {
    rtp = {
      disabled_plugins = {
        "2html_plugin", "tohtml", "getscript", "getscriptPlugin",
        "gzip", "logipat", "netrw", "netrwPlugin", "netrwSettings",
        "netrwFileHandlers", "matchit", "tar", "tarPlugin",
        "rrhelper", "spellfile_plugin", "vimball", "vimballPlugin",
        "zip", "zipPlugin", "tutor", "rplugin", "syntax",
        "synmenu", "optwin", "compiler", "bugreport", "ftplugin",
      },
    },
  },
})

-- ─── Step 3: Boot Anvil ───
require("anvil").boot({
  languages = {
    "typescript", "html", "json", "markdown",
    -- "rust", "go", "python", "lua", "bash", "docker",
  },
  ui = {
    colorscheme = "catppuccin",
    strategy    = "auto",
  },
  log = {
    level   = "info",
    to_file = false,
  },
})
```

### `lua/chadrc.lua`

NvChad configuration file. Controls base46 theme, statusline, tabufline, and nvdash. NvChad reads this file directly; Anvil populates it from `config.lua`.

<!-- file: lua/chadrc.lua -->
```lua

--- Theme and UI chrome are NvChad-native; everything else delegates to Anvil.
---@type ChadrcConfig
local M = {}

-- ─── Theme (base46) ───
M.base46 = {
  theme = "catppuccin",  -- Synced with config.ui.colorscheme
  transparency = false,
  hl_override = {
    Comment      = { italic = true },
    ["@comment"] = { italic = true },
  },
}

-- ─── UI ───
M.ui = {
  statusline = {
    theme = "default",
    separator_style = "round",
  },
  tabufline = {
    enabled  = true,
    lazyload = true,
  },
  nvdash = {
    load_on_startup = true,
    header = {
      "                                       ",
      "   ╔═══════════════════════════╗       ",
      "   ║       ⚒  ANVIL  ⚒         ║       ",
      "   ║     AI-Powered Forge      ║       ",
      "   ║       for Neovim          ║       ",
      "   ╚═══════════════════════════╝       ",
      "                                       ",
    },
    buttons = {
      { txt = "  Find File",   keys = "ff", cmd = "Telescope find_files" },
      { txt = "  Recent Files", keys = "fr", cmd = "Telescope oldfiles" },
      { txt = "  Find Word",   keys = "fg", cmd = "Telescope live_grep" },
      { txt = "󰊢  Git Status",  keys = "gg", cmd = "LazyGit" },
      { txt = "󰚩  AI Chat",     keys = "ac", cmd = "CodeCompanionChat" },
      { txt = "  Themes",      keys = "th", cmd = "lua require('nvchad.themes').open()" },
      { txt = "  Mappings",    keys = "ch", cmd = "NvCheatsheet" },
    },
  },
}

-- NvChad uses this to find user plugin overrides
M.plugins = "plugins"

-- NvChad mappings are handled by Anvil's core/keys.lua
-- We don't use NvChad's mapping system
M.mappings = {}

return M
```

## NvChad Hook Files

NvChad expects three hook files in `lua/`: `options.lua`, `mappings.lua`, and `autocmds.lua`. In Anvil, these are intentionally **empty no-ops** because all logic is handled by Anvil's core modules during boot. The files exist solely to prevent NvChad from complaining about missing files.

### `lua/options.lua`

NvChad options hook. Delegates to Anvil core.

<!-- file: lua/options.lua -->
```lua
--- NvChad options hook
--- Delegates to anvil.core.options which is already applied during boot.
--- This file exists because NvChad expects it; it's intentionally minimal.
--- All options are defined in lua/anvil/core/options.lua

-- Options are applied during anvil.boot() → core/options.apply()
-- This file is a no-op to prevent NvChad from complaining about missing file.
```

### `lua/mappings.lua`

NvChad mappings hook. Delegates to Anvil core.

<!-- file: lua/mappings.lua -->
```lua

--- This file exists because NvChad expects it; it's intentionally minimal.

-- Keymaps are applied during anvil.boot() → core/keys.setup()
```

## Framework Detection

Anvil detects the active framework at runtime via `ui.detect_strategy()`. This determines which bridge and UI modules to load.

```text
detect_strategy()
│
├── config.ui.strategy == "nvchad"     → return "nvchad"
├── config.ui.strategy == "astronvim"  → return "astronvim"
├── config.ui.strategy == "standalone" → return "standalone"
│
├── config.ui.strategy == "auto" (default):
│   ├── pcall(require, "nvchad")       → success → "nvchad"
│   ├── pcall(require, "astronvim")    → success → "astronvim"
│   └── fallback                       → "standalone"
│
└── Result used by:
    ├── ui/ layer      → load ui/<strategy>/ modules
    ├── bridge/ layer  → load bridge/<strategy>/ modules
    └── health check   → report active strategy
```

### `lua/anvil/ui/init.lua`

<!-- lua/anvil/ui/init.lua -->
```lua
--- Anvil UI strategy detection
--- Determines which framework bridge to use
--- Depends on: config
---@class AnvilUI
local M = {}

---@type string|nil
M._strategy = nil

--- Detect the active UI strategy
---@return "nvchad"|"astronvim"|"standalone"
function M.detect_strategy()
  if M._strategy then return M._strategy end

  local config_ok, config = pcall(require, "anvil.config")
  if config_ok then
    local cfg = config.get()
    if cfg.ui and cfg.ui.strategy and cfg.ui.strategy ~= "auto" then
      M._strategy = cfg.ui.strategy
      return M._strategy
    end
  end

  -- Auto-detect
  if pcall(require, "nvchad") then
    M._strategy = "nvchad"
  elseif pcall(require, "astronvim") then
    M._strategy = "astronvim"
  else
    M._strategy = "standalone"
  end

  return M._strategy
end

return M
```

### `lua/anvil/bridge/nvchad/init.lua`

NvChad-specific boot integration. Handles anything that requires NvChad APIs.

<!-- file: lua/anvil/bridge/nvchad/init.lua -->
```lua
--- Anvil NvChad bridge
--- Handles NvChad-specific integration that can't be done in framework-agnostic code.
--- This module is only loaded when NvChad is detected.
--- Depends on: core/icons, core/events
---@class AnvilBridgeNvChad
local M = {}

--- Apply NvChad-specific settings
--- Called during anvil.boot() when NvChad is detected
function M.apply()
  -- base46 theme integration
  -- NvChad compiles themes at startup; Anvil's colorscheme
  -- preference is passed through chadrc.lua
  local base46_ok = pcall(require, "base46")
  if base46_ok then
    -- base46 auto-compiles; nothing to do here
  end

  -- Integrate Anvil events with NvChad
  local events_ok, events = pcall(require, "anvil.core.events")
  if events_ok then
    events.on("ai:preset_changed", function(args)
      -- Update statusline when AI preset changes (if statusline shows AI info)
      vim.cmd("redrawstatus")
    end)
  end

  -- Statusline customization
  -- NvChad provides a built-in statusline; Anvil adds
  -- AI and voice indicators via the statusline module

  -- Tabufline (buffer line)
  -- NvChad's tabufline is used as-is; Anvil does not
  -- override buffer management UI

  local logger_ok, logger = pcall(require, "anvil.core.logger")
  if logger_ok then
    logger.debug("NvChad bridge applied")
  end
end

--- Check if NvChad is available
---@return boolean
function M.is_available()
  local has_ui = pcall(require, "nvchad")
  local has_base46 = pcall(require, "base46")
  return has_ui and has_base46
end

return M
```

NVIM_APPNAME Isolation

Anvil uses Neovim's built-in `NVIM_APPNAME` mechanism (available since Neovim 0.9) to achieve complete isolation from other configurations on the same machine.

How It Works

```text
NVIM_APPNAME affects all XDG-derived paths:

  NVIM_APPNAME=anvil nvim
  │
  ├── config:  ~/.config/anvil/        (instead of ~/.config/nvim/)
  ├── data:    ~/.local/share/anvil/   (instead of ~/.local/share/nvim/)
  ├── state:   ~/.local/state/anvil/   (instead of ~/.local/state/nvim/)
  ├── cache:   ~/.cache/anvil/         (instead of ~/.cache/nvim/)
  └── log:     ~/.local/state/anvil/log/ (Anvil log file)
```

Coexistence Matrix

Multiple Neovim configurations can exist simultaneously without any interference:

```text
┌─────────────┬──────────────────────┬──────────────────────────┐
│ Command     │ Config directory     │ Data directory           │
├─────────────┼──────────────────────┼──────────────────────────┤
│ nvim        │ ~/.config/nvim/      │ ~/.local/share/nvim/     │
│ chad        │ ~/.config/nvchad/    │ ~/.local/share/nvchad/   │
│ anvil       │ ~/.config/anvil/     │ ~/.local/share/anvil/    │
│ astro       │ ~/.config/astronvim/ │ ~/.local/share/astronvim/│
└─────────────┴──────────────────────┴──────────────────────────┘

Each has its own:
  • Plugin installations (lazy.nvim store)
  • Mason-installed tools (LSP servers, formatters, linters)
  • Treesitter parsers
  • Session files and undo history
  • Shada (command history, marks, registers)
  • Log files
```

Recommended Shell Aliases

```bash
# ~/.bashrc or ~/.zshrc

# For headless operations (scripts, CI)
export ANVIL_APPNAME=anvil

```

NvChad Inside Anvil vs Standalone NvChad

A user may have both a standalone NvChad installation and Anvil (which includes NvChad internally). These are **completely independent**:

```text
Standalone NvChad                    Anvil (with NvChad inside)
─────────────────                    ──────────────────────────
NVIM_APPNAME=nvchad                  NVIM_APPNAME=anvil

~/.config/nvchad/                    ~/.config/anvil/
├── init.lua (NvChad default)        ├── init.lua (Anvil bootstrap)
├── lua/chadrc.lua (user's)          ├── lua/chadrc.lua (Anvil's)
└── lua/plugins/ (user's)            ├── lua/plugins/ (Anvil specs)
                                     ├── lua/anvil/ (core, lang, ai...)
                                     └── lua/user/ (user layer)

~/.local/share/nvchad/lazy/          ~/.local/share/anvil/lazy/
├── NvChad/ (maybe v2.5)             ├── NvChad/ (maybe v2.5)
├── telescope.nvim/                  ├── telescope.nvim/
└── ... (user's plugins)             └── ... (Anvil's plugins)

Different plugins, different Mason tools,
different themes, different everything.
```

Bridge for Other Frameworks (Path C)

The bridge layer is designed to support additional frameworks in the future (ADR-024). Adding a new framework requires:

```text
To add AstroNvim support:

1. Create lua/anvil/bridge/astronvim/init.lua
   └── AstroNvim-specific boot integration

2. Create lua/anvil/ui/astronvim/
   ├── theme.lua       ← AstroNvim theme system
   ├── statusline.lua  ← Heirline configuration
   └── dashboard.lua   ← Alpha/dashboard integration

3. Create lua/plugins-astronvim/ (or separate repo)
   └── AstroNvim-idiomatic LazySpec files

4. Override strategy points in editor layer:
   editor/lsp.lua      → use AstroLSP instead of lspconfig
   editor/dap.lua      → use AstroNvim DAP integration
   editor/test.lua     → (usually unchanged)

5. Zero changes to:
   core/   ← events, cache, logger, env, keys
   lang/   ← language packs, registry, engine
   ai/     ← providers, context, agents, MCP
   voice/  ← STT, commands, interpreter
```

Strategy Points

The editor layer exposes overridable functions that a bridge can replace:

```lua
-- editor/lsp.lua — default implementation
M.register_server = function(server, opts)
  require("lspconfig")[server].setup(opts)
end

-- bridge/astronvim/init.lua could override:
-- local editor_lsp = require("anvil.editor.lsp")
-- editor_lsp.register_server = function(server, opts)
--   require("astrolsp").config[server] = opts
-- end
```

Strategy points exist in:

| Module | Function | Purpose |
|---|---|---|
| `editor/lsp.lua` | `register_server()` | LSP server registration |
| `editor/lsp.lua` | `build_capabilities()` | LSP capability negotiation |
| `editor/dap.lua` | `register_adapter()` | DAP adapter registration |
| `editor/dap.lua` | `register_configuration()` | DAP launch config |
| `editor/test.lua` | `register_adapter()` | Neotest adapter registration |

Health Check

The bridge reports its status in `:checkhealth anvil`:

```text
Anvil UI
  ✓ UI strategy: nvchad
  ✓ Colorscheme: catppuccin
  ✓ NvChad loaded (v2.5)
  ✓ base46 theme compiled
```

When NvChad is not present:

```text
Anvil UI
  ✓ UI strategy: standalone
  ✓ Colorscheme: catppuccin
  ℹ NvChad not detected — using standalone mode
```
