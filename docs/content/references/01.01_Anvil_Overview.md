# Anvil — AI-Powered Forge for Neovim

## What is it

Anvil is a comprehensive NvChad-based user configuration that transforms Neovim into a full-featured IDE with deeply integrated AI. It is not a plugin or a distribution — it is a complete working environment where AI is a first-class subsystem alongside LSP, debugging, testing, and Git.

Anvil is designed as a replacement for the VSCode + Cline / Claude Code stack for those who prefer the terminal and open-source tools.

## Who is it for

- Developers who want the comfort of a full IDE inside Neovim
- Those who use AI coding assistants and want to control them from the editor
- Teams working with multiple languages in a single environment
- Users who value reproducibility: one configuration — on every machine

## Key principles

### Language-first

The language determines everything else. Each language pack is a single file that declaratively describes the LSP server, formatter, linter, debugger, test framework, build tasks, and AI context. Adding a new language means creating one file from a template. Anvil picks up the rest automatically.

### AI-native

AI is not bolted on — it is woven into every layer. Diagnostics, test results, project structure, Git changes — all of this is automatically collected into context and can be sent to an AI agent with a single action. At the same time, AI is never forced on you: inline completions are off by default, chat opens explicitly.

### Multi-provider with presets

All AI tools work through OpenAI-compatible endpoints. Anvil supports multiple providers simultaneously — cloud (OpenRouter, etc.), local (Ollama, LM Studio, vLLM), and corporate. Each interaction type (chat, inline completion, architect mode, agents) can use a different provider and model. Presets allow instant switching between configurations: corporate (private provider only), standard (cloud + local), open-source (sponsored provider). No subscriptions to GitHub Copilot or Claude Code required. Switching the entire AI stack means selecting a preset.

### Portable

Works on Linux and macOS. Installs with a single script. The configuration lives in a Git repository and uses NVIM_APPNAME isolation to coexist with other Neovim configurations.

### Framework-agnostic core

Anvil's core logic (language engine, AI layer, context builder, cache, events) is framework-independent Lua code. The framework (NvChad) provides only UI chrome and plugin bootstrapping. This design enables future migration to other frameworks without rewriting business logic.

## What is inside

### Editor

- **LSP** — completion, go-to-definition, refactoring, inlay hints
- **Treesitter** — highlighting, function/class navigation, text objects
- **Formatting** — conform.nvim, format-on-save
- **Linting** — nvim-lint, integration with language-specific linters
- **Debugging** — nvim-dap with UI, support for Node.js, Python, Go, Rust, C/C++
- **Testing** — neotest with adapters for each language
- **Completion** — nvim-cmp with LSP, snippets, paths

### AI ecosystem

- **CodeCompanion** — primary AI agent: chat, inline commands, slash commands, MCP
- **minuet-ai** — inline completion on the fly, explicitly toggled with F2
- **wtf.nvim** — AI-powered diagnostic error explanations
- **MCP** — external tool integration: filesystem, databases, browser, search
- **External agents** — Aider, OpenCode launch from the editor with context

### AI provider system

Anvil uses a **provider → model → slot → preset** architecture:

- **Providers**: named endpoints (OpenRouter, Ollama, corporate LLM, etc.)
- **Models**: specific models available on each provider
- **Slots**: interaction types (chat, inline, agent, architect, fast, local) — each points to a model
- **Presets**: named configurations that assign models to all slots at once

Switch presets instantly with `:AnvilPreset` or `<leader>aPp`. Change a single slot with `:AnvilSlot` or `<leader>aPs`. Save your current configuration as a new preset with `:AnvilSavePreset`.

All configuration is stored in `config/ai-providers.json` — no environment variables needed.

### Context for AI

Anvil automatically collects and caches:

- project structure and key files (README, package.json, Cargo.toml...)
- diagnostics for the current buffer and the entire project
- test results
- Git diff
- cursor position with treesitter awareness (current function, class)

All of this is available through slash commands in chat (`/project`, `/diagnostics`, `/tests`, `/diff`, `/url`) and can be passed to external tools.

### Git

gitsigns, lazygit, diffview, blame, AI review of staged changes, AI-generated commit messages.

### Workflow

overseer (build tasks), toggleterm (terminals), harpoon (file bookmarks), sessions (auto-save/restore).

## Requirements

- Neovim ≥ 0.10
- Git, Node.js ≥ 18, npm
- ripgrep, fd — for search
- Language toolchains as needed (rustup, go, python3...)
- Nerd Font in the terminal
- OpenAI-compatible API endpoint for AI (OpenRouter, Ollama, etc.)

## Quick start

```bash
# 1. Clone the Anvil configuration
git clone <repo-url> ~/.local/src/anvil

# 2. Install
cd ~/.local/src/anvil
./scripts/install.sh

# 3. Launch
NVIM_APPNAME=anvil nvim

# 4. Configure AI (in editor)
:AnvilProviderEdit   # edit config/ai-providers.json
# or
:AnvilPreset         # pick a preset

# 5. Verify
:checkhealth anvil
```

## Typical usage scenarios

- **Quick error fix** — you see a red underline → `<leader>ae` (AI explains) → `<leader>af` (AI fixes) → accept or reject the diff.
- **New feature with planning** — `<leader>ap` (Architect mode) → describe the task → AI presents a plan → type "go" → AI implements → `/tests` to verify.
- **Heavy task** — `<leader>Aa` (pass context to Aider) → Aider edits files → return to Neovim → `<leader>ta` (run tests) → `<leader>at` (send failures to AI).
- **Code review before commit** — `git add -p` → `<leader>ar` (AI review) → fix → `<leader>aG` (AI commit message).
- **Exploring an unfamiliar project** — `:AnvilIndex` → `<leader>ac` (chat) → `/project` → `/url https://docs.example.com` → ask questions.
- **Switching AI context** — working on a corporate project → `:AnvilPreset corporate` → all AI traffic goes through private provider. Switch to open-source work → `:AnvilPreset default`.
