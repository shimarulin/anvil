# Anvil — Lang Pack: Rust

Complete Rust development environment: rust-analyzer via rustaceanvim,
debugging with codelldb, testing with neotest, crate management, and
Rust-specific AI context.

## Overview

| Component | Tool | Notes |
|---|---|---|
| LSP | rust-analyzer | Managed by rustaceanvim (not lspconfig) |
| Treesitter | `rust`, `toml` | Syntax highlighting, text objects |
| Formatter | rustfmt | Via rust-analyzer, edition 2021 |
| Linter | clippy | Via rust-analyzer checkOnSave |
| DAP | codelldb | Via rustaceanvim debuggables |
| Test | neotest-rust | Cargo test integration |
| Crates | crates.nvim | Cargo.toml dependency management |

## Architecture Note

Unlike most languages, Rust uses **rustaceanvim** which manages
rust-analyzer directly — it does NOT go through `lspconfig`. The
language pack marks this with `lsp.managed_by_plugin = true` so
Anvil's lang engine skips lspconfig registration.

```
┌─────────────────────────────────────────────────────────────┐
│                    Rust Lang Pack                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  rustaceanvim ──→ manages rust-analyzer lifecycle           │
│               ──→ provides LSP features (hover, goto, etc.) │
│               ──→ provides DAP integration (debuggables)    │
│               ──→ provides code actions (expand macro, etc.)│
│               ──→ provides runnables (cargo run/test)       │
│                                                             │
│  crates.nvim  ──→ Cargo.toml: versions, features, docs     │
│               ──→ cmp source for dependency completion      │
│                                                             │
│  neotest-rust ──→ test discovery and execution              │
│               ──→ inline test results                       │
│                                                             │
│  overseer     ──→ cargo build/run/test/clippy/bench/doc     │
│                                                             │
│  AI context   ──→ Rust-specific system prompt               │
│               ──→ Rust-specific review rules                │
└─────────────────────────────────────────────────────────────┘
```

## Lang Engine Integration

### Update to `lua/anvil/lang/init.lua`

The Rust pack uses `lsp.managed_by_plugin = true`. The lang engine
must respect this flag:

```lua
--- In anvil/lang/init.lua, update lsp_servers():

--- Collect all LSP server configs for lspconfig
--- Skips servers managed by external plugins (e.g., rustaceanvim)
---@return table<string, table>
function M.lsp_servers()
  local servers = {}
  for _, name in ipairs(M._enabled) do
    local pack = M._registry[name]
    if pack and pack.lsp then
      -- Skip servers managed by their own plugins
      if not pack.lsp.managed_by_plugin then
        servers[pack.lsp.server] = pack.lsp.settings or {}
      end
    end
  end
  return servers
end

--- Collect mason packages
--- Includes ALL servers (even plugin-managed ones need mason install)
---@return string[]
function M.mason_ensure_installed()
  local tools = {}
  for _, name in ipairs(M._enabled) do
    local pack = M._registry[name]
    if not pack then goto continue end

    -- LSP (always install via mason, even if managed by plugin)
    if pack.lsp then
      table.insert(tools, pack.lsp.server)
    end
    -- DAP
    if pack.dap then
      table.insert(tools, pack.dap.adapter)
    end
    -- Formatter (skip if managed by LSP)
    if pack.formatter and not pack.formatter.managed_by_lsp then
      table.insert(tools, pack.formatter.tool)
    end
    -- Linter
    if pack.linter then
      table.insert(tools, pack.linter.tool)
    end

    ::continue::
  end
  return vim.fn.uniq(vim.fn.sort(tools))
end

--- Collect conform formatters
--- Skips formatters managed by LSP (e.g., rustfmt via rust-analyzer)
---@return table<string, string[]>
function M.formatters_by_ft()
  local formatters = {}
  for _, name in ipairs(M._enabled) do
    local pack = M._registry[name]
    if pack and pack.formatter and not pack.formatter.managed_by_lsp then
      for _, ft in ipairs(pack.filetypes) do
        formatters[ft] = { pack.formatter.tool }
      end
    end
  end
  return formatters
end
```

## Recommended Toolchain Setup

```bash
# ─── Install Rust ───
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# ─── Components ───
rustup component add rust-analyzer  # LSP
rustup component add rustfmt        # formatter
rustup component add clippy         # linter
rustup component add rust-src       # source for goto definition

# ─── Useful cargo extensions ───
cargo install cargo-edit            # cargo add/rm/upgrade
cargo install cargo-watch           # watch for changes
cargo install cargo-expand          # expand macros
cargo install cargo-audit           # security audit
cargo install cargo-udeps           # find unused deps (nightly)
cargo install cargo-nextest         # faster test runner
cargo install cargo-deny            # license/advisory checking

# ─── Mason will install ───
# rust-analyzer (redundant if installed via rustup, but mason manages it)
# codelldb (DAP adapter)
```

### Workflow: Develop a new feature

```
1. Open .rs file
   → rustaceanvim starts rust-analyzer automatically
   → inlay hints show types, lifetimes, chains
   → clippy diagnostics appear inline

2. Write code
   → completion via nvim-cmp (rust-analyzer source)
   → signature help shows function parameters
   → auto-import on completion confirm

3. <leader>rr     → pick runnable (cargo run, examples, etc.)
4. <leader>rt     → pick and run specific test
5. <leader>tt     → run nearest test (neotest)
6. <leader>re     → explain error under cursor (rust-analyzer)

7. Format on save → rust-analyzer runs rustfmt automatically
```

### Workflow: Debug a Rust program

```
1. <leader>db     → set breakpoint
2. <leader>rd     → pick debuggable (cargo target)
   → codelldb starts, DAP UI opens
3. <F10>/<F11>    → step over/into
4. <leader>de     → eval expression
5. <leader>dt     → terminate
```
