# Anvil — Architecture

Anvil is a comprehensive NvChad user configuration where AI is a first-class subsystem alongside LSP, languages, debugging, UI, and workflow.

## Philosophy

```text
┌─────────────────────────────────────────────────────┐
│                      ANVIL                          │
│          "One config to rule them all"              │
│                                                     │
│  1. Language-first  — language defines everything   │
│  2. Consistency     — same patterns everywhere      │
│  3. AI-native       — AI is woven into every layer  │
│  4. Portable        — works on Linux and macOS      │
│  5. Declarative     — describe WHAT, not HOW        │
│  6. Discoverable    — find everything via :Anvil    │
│  7. Separable       — core logic ≠ framework chrome │
│  8. Extensible      — user & community layers       │
└─────────────────────────────────────────────────────┘
```

### External layers

```text
┌─────────────────────────────────────────────────────────────────┐
│                          ANVIL                                  │
│                     (base repository)                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  lua/anvil/lang/          ← built-in packs (priority 1)        │
│  lua/anvil/voice/         ← built-in voice commands             │
│  lua/anvil/core/keys.lua  ← built-in keymaps                   │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  lua/anvil-community/lang/  ← community packs (priority 2)     │
│  (from runtimepath — lazy.nvim plugins)                         │
│                                                                 │
│  Examples:                                                      │
│    anvil-editor/anvil-community-langs  (curated collection)     │
│    someone/anvil-lang-elixir           (individual pack)        │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  lua/user/                  ← user layer (priority 3, highest)  │
│  (gitignored OR separate repo)                                  │
│                                                                 │
│  ├── init.lua               ← entry point                      │
│  ├── voice/commands.lua     ← user voice commands               │
│  ├── keys.lua               ← keymap overrides                  │
│  ├── commands.lua           ← text command overrides             │
│  └── lang/                                                      │
│      └── rust.lua           ← override built-in Rust pack       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

Boot sequence:
  Phase 1-5: Core Anvil (unchanged)
  Phase 6:   User layer (lua/user/init.lua)

Language resolution:
  user/lang/rust.lua  >  anvil-community/lang/rust.lua  >  anvil/lang/rust.lua
  (same name → highest priority wins)

Voice command resolution:
  user voice commands  >  lang pack voice commands  >  built-in voice commands
  (checked in this order; first match wins)
```

This solution allows:
- Update the base Anvil via `git pull` without conflicts
- Add languages without modifying the main repository (community plugins)
- Override everything at the user level (voice commands, keys, language packages)
- Extend built-in packages instead of complete replacement (`require("anvil.lang.rust")` + modification)

## Layer dependency rules

```text
Bridge   → may call anything below
UI       → core/icons, core/events
Editor   → core/keys, core/icons, lang (for data)
Git      → core/events (optional)
Workflow → core/events (optional)
Voice    → core/events, core/logger, ai (for interpretation)
Lang     → core/logger, core/events
AI       → core/env, core/cache, core/logger, core/events, lang (for ai_context)
Core     → NOTHING (only vim.* built-in APIs)
```

No circular dependencies. No upward calls (core never calls ai, lang never calls editor). AI layer initializes lazily on first AI command. Voice layer initializes lazily on first voice command.

## Boot Process

```text
init.lua (NvChad bootstrap)
│
├── lazy.nvim setup
│   └── plugins/ loaded (including anvil-bridge.lua)
│
└── require("anvil").boot(opts)
    │
    ├── Phase 1: Core (synchronous)
    │   config.apply() → logger.setup()
    │   → events.setup() → options.apply()
    │   → autocmds.setup() → keys.setup()
    │
    ├── Phase 2: Platform detection
    │   platform.apply()
    │
    ├── Phase 3: Language registration
    │   lang.setup(config.languages)
    │   Scans: anvil/lang/ → anvil-community/lang/ → user/lang/
    │
    ├── Phase 4: Commands
    │   :Anvil, :AnvilChat, :AnvilAsk, :AnvilIndex, etc.
    │
    ├── Phase 5: Ready
    │   events.emit("ready")
    │
    └── Phase 6: User layer
        require("user").setup(config)
        → user voice commands
        → user keymap overrides
        → user text commands
```

AI layer initializes lazily on first AI command.
Voice layer initializes lazily on first voice command.
Voice commands from language packs are registered when voice subsystem initializes.

## Adding a new language

```text
┌─────────────────────────────────────────────────────┐
│  Adding a new language = creating 1 file            │
│  lua/anvil/lang/elixir.lua                          │
│                                                     │
│  That file automatically:                           │
│  ✓ Registers the LSP server                         │
│  ✓ Adds treesitter parsers                          │
│  ✓ Configures formatting                            │
│  ✓ Configures linting                               │
│  ✓ Adds DAP configuration                           │
│  ✓ Registers neotest adapter                        │
│  ✓ Creates overseer tasks                           │
│  ✓ Passes AI context for the language               │
│  ✓ Sets up language-specific keybindings            │
│  ✓ Loads additional plugins                         │
│  ✓ Registers language-specific voice commands       │
│                                                     │
│  Three places to put the file:                      │
│  1. lua/anvil/lang/         (built-in, PR to Anvil) │
│  2. lua/anvil-community/lang/ (community plugin)    │
│  3. lua/user/lang/          (personal, gitignored)  │
│                                                     │
│  Everything else Anvil handles automatically.       │
└─────────────────────────────────────────────────────┘
```

## Future: Path A → C (multi-framework)

When adding a second framework (e.g., AstroNvim):

1. Create `lua/anvil/ui/astronvim/` — theme, statusline
2. Create `lua/anvil/bridge/astronvim/` — boot integration, strategy overrides
3. Create a separate `lua/plugins-astronvim/` (or separate repo)
4. Override strategy points in editor layer
5. `core/`, `lang/`, `ai/`, `voice/`, `user/` — **zero changes**
