# Anvil — Lang Pack: Python

Complete Python development environment: basedpyright for type checking,
ruff for linting and formatting, debugpy for debugging, pytest via neotest,
virtual environment management, and Python-specific AI context.

## Overview

| Component | Tool | Notes |
|---|---|---|
| LSP (types) | basedpyright | Type checking, completion, goto |
| LSP (lint) | ruff | Code actions (fix, organize imports) |
| Treesitter | `python`, `toml`, `requirements`, `rst` | Full syntax coverage |
| Formatter | ruff format | Via conform.nvim (replaces black) |
| Linter | ruff check | Via nvim-lint (replaces flake8/pylint/isort) |
| DAP | debugpy | 7 debug configurations |
| Test | neotest-python | pytest integration |
| Venv | venv-selector.nvim | Auto-detect and switch virtualenvs |

## Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                    Python Lang Pack                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  basedpyright ──→ type checking, completion, hover, goto    │
│  (LSP)        ──→ auto-import, rename, find references      │
│               ──→ inlay hints (variable types, return types)│
│               ──→ respects pyrightconfig.json / pyproject   │
│                                                             │
│  ruff (LSP)   ──→ code actions (auto-fix, organize imports) │
│               ──→ runs alongside basedpyright               │
│                                                             │
│  conform      ──→ ruff format (on save)                     │
│               ──→ ruff check --fix (auto-fix on format)     │
│                                                             │
│  nvim-lint    ──→ ruff check (diagnostics)                  │
│               ──→ mypy (optional, via tasks)                │
│                                                             │
│  debugpy      ──→ debug file, module, Django, FastAPI, etc. │
│  (DAP)        ──→ pytest debugging                          │
│               ──→ remote attach                             │
│                                                             │
│  neotest      ──→ neotest-python (pytest runner)            │
│                                                             │
│  venv-selector──→ detect .venv, venv, poetry, conda, pyenv │
│               ──→ switch venv → restarts LSP automatically  │
│                                                             │
│  overseer     ──→ python run, pytest, ruff, mypy, pip, etc. │
│                                                             │
│  AI context   ──→ Python-specific system prompt             │
│               ──→ Python-specific review rules              │
└─────────────────────────────────────────────────────────────┘
```

### Dual LSP Strategy

Python uses **two LSP servers simultaneously**:

| Server | Role | Formatting | Diagnostics |
|---|---|---|---|
| basedpyright | Types, completion, goto, hover | ❌ disabled | Type errors |
| ruff | Code actions, organize imports | ❌ disabled (conform) | Lint warnings |

This is intentional — basedpyright excels at type analysis while ruff
excels at linting and quick fixes. They complement each other.

## Lang Engine Updates

### Support for `extra_servers` in `lua/anvil/lang/init.lua`

The Python pack uses two LSP servers. The lang engine needs to handle
`extra_servers`:

```lua
--- Collect all LSP server configs for lspconfig
--- Includes extra_servers from lang packs (e.g., ruff alongside basedpyright)
---@return table<string, table>
function M.lsp_servers()
  local servers = {}
  for _, name in ipairs(M._enabled) do
    local pack = M._registry[name]
    if pack and pack.lsp then
      -- Primary server
      if not pack.lsp.managed_by_plugin then
        servers[pack.lsp.server] = {
          settings = pack.lsp.settings or {},
          on_attach = pack.lsp.on_attach,
          capabilities = pack.lsp.capabilities,
        }
      end

      -- Extra servers (e.g., ruff alongside basedpyright)
      if pack.lsp.extra_servers then
        for _, extra in ipairs(pack.lsp.extra_servers) do
          servers[extra.server] = {
            settings = extra.settings or {},
            on_attach = extra.on_attach,
            capabilities = extra.capabilities,
          }
        end
      end
    end
  end
  return servers
end

--- Mason ensure_installed — includes extra servers
---@return string[]
function M.mason_ensure_installed()
  local tools = {}
  for _, name in ipairs(M._enabled) do
    local pack = M._registry[name]
    if not pack then goto continue end

    if pack.lsp then
      table.insert(tools, pack.lsp.server)
      -- Extra servers
      if pack.lsp.extra_servers then
        for _, extra in ipairs(pack.lsp.extra_servers) do
          table.insert(tools, extra.server)
        end
      end
    end
    if pack.dap then table.insert(tools, pack.dap.adapter) end
    if pack.formatter and not pack.formatter.managed_by_lsp then
      table.insert(tools, pack.formatter.tool)
    end
    if pack.linter then table.insert(tools, pack.linter.tool) end

    ::continue::
  end
  return vim.fn.uniq(vim.fn.sort(tools))
end
```

## Recommended Toolchain Setup

```bash
# ─── Install Python ───
# macOS: brew install python@3.12
# Ubuntu: sudo apt install python3 python3-pip python3-venv
# Arch: sudo pacman -S python python-pip

# ─── Verify ───
python3 --version  # should be 3.10+

# ─── Global tools (via pipx — recommended) ───
pip install pipx
pipx ensurepath

pipx install ruff           # linter + formatter
pipx install mypy           # static type checker
pipx install pytest         # test runner (also install per-project)
pipx install ipython        # enhanced REPL
pipx install poetry         # package manager (optional)
pipx install pdm            # package manager (optional)

# ─── uv (fast Python package installer) ───
# https://docs.astral.sh/uv/
curl -LsSf https://astral.sh/uv/install.sh | sh

# ─── Per-project setup ───
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"  # or: uv pip install -e ".[dev]"

# ─── Mason will install ───
# basedpyright, ruff, debugpy
```

## Workflow Examples

### Workflow: Start a new Python project

```
1. Create project structure
   mkdir myproject && cd myproject
   python3 -m venv .venv
   source .venv/bin/activate

2. Open in Neovim
   → basedpyright starts (detects .venv automatically)
   → ruff LSP starts alongside

3. If wrong venv:
   <leader>rv     → telescope picker shows all detected venvs
   → Select correct one → LSP restarts automatically

4. Write code
   → Type hints completion from basedpyright
   → Ruff diagnostics appear inline
   → Format on save: organize imports + ruff format
```

### Workflow: Debug a FastAPI application

```
1. <leader>db     → set breakpoint in endpoint handler
2. <leader>dc     → continue → select "FastAPI (uvicorn)"
   → Enter app module: "main:app"
   → uvicorn starts with debugpy attached
3. Send request to endpoint (curl, browser, etc.)
4. Breakpoint hits → DAP UI shows variables
5. <F10>/<F11>    → step through code
6. <leader>de     → eval expression
7. <leader>dt     → terminate
```

### Workflow: Test-driven development

```
1. Write test in tests/test_feature.py
2. <leader>tt     → run nearest test (neotest + pytest)
3. Test fails → red indicator inline
4. <leader>tf     → send failure to AI
5. AI suggests fix
6. Implement fix
7. <leader>tt     → re-run → green
8. <leader>tT     → run all tests in file
9. <leader>ta     → run entire test suite
```

### Workflow: AI-assisted Python development

```
1. <leader>ac     → open AI chat
2. /project       → add project context (pyproject.toml included)
3. Ask: "Implement a retry decorator with exponential backoff"
   → AI knows Python conventions from lang pack system_prompt
   → Uses type hints, dataclasses, proper exception handling
   → Includes pytest tests with parametrize

4. <leader>ar     → AI code review
   → Checks for mutable defaults, bare excepts, missing type hints
   → Uses Python-specific review_rules

5. <leader>ag     → generate tests
   → AI generates pytest tests with fixtures and parametrize
```
