# Anvil — Lang Pack: Go

Complete Go development environment: gopls with full configuration,
debugging with delve, testing with neotest-golang, struct tag management,
and Go-specific AI context.

## Overview

| Component | Tool | Notes |
|---|---|---|
| LSP | gopls | Via lspconfig, gofumpt enabled |
| Treesitter | `go`, `gomod`, `gowork`, `gosum`, `goctl` | Full syntax coverage |
| Formatter | gofumpt + goimports | Via conform.nvim |
| Linter | golangci-lint | Via nvim-lint |
| DAP | delve | 4 debug configurations |
| Test | neotest-golang | With race detection |
| Extras | go.nvim | Struct tags, interface stubs, test generation |

## Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                      Go Lang Pack                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  gopls (LSP)  ──→ completion, diagnostics, hover, goto     │
│               ──→ code actions (organize imports, fill...)  │
│               ──→ codelenses (run test, generate, tidy)     │
│               ──→ inlay hints (types, params, ranges)       │
│               ──→ staticcheck integration                   │
│               ──→ analyses (shadow, fieldalignment, etc.)   │
│                                                             │
│  conform      ──→ gofumpt (strict formatting)              │
│               ──→ goimports (import management)             │
│                                                             │
│  nvim-lint    ──→ golangci-lint (meta-linter)              │
│                                                             │
│  delve (DAP)  ──→ debug file, test, package, attach        │
│                                                             │
│  neotest      ──→ neotest-golang (test discovery + run)    │
│                                                             │
│  go.nvim      ──→ struct tags (add/remove/clear)           │
│               ──→ interface implementation stubs            │
│               ──→ test generation (gotests)                 │
│               ──→ fill struct fields                        │
│               ──→ if err != nil boilerplate                 │
│                                                             │
│  overseer     ──→ go build/run/test/vet/generate/tidy/...  │
│                                                             │
│  AI context   ──→ Go-specific system prompt                │
│               ──→ Go-specific review rules                 │
└─────────────────────────────────────────────────────────────┘
```

## Conform Configuration

The Go lang pack uses two formatters in sequence. This requires
a small addition to how Anvil's lang engine builds the conform config:

### Updated formatter handling in `lua/anvil/lang/init.lua`

```lua
--- Collect conform formatters
--- Handles multi-formatter chains and LSP-managed formatters
---@return table<string, table>
function M.formatters_by_ft()
  local formatters = {}
  for _, name in ipairs(M._enabled) do
    local pack = M._registry[name]
    if pack and pack.formatter and not pack.formatter.managed_by_lsp then
      for _, ft in ipairs(pack.filetypes) do
        -- Support formatter chains
        if pack.formatter.chain then
          formatters[ft] = pack.formatter.chain
        else
          formatters[ft] = { pack.formatter.tool }
        end
      end
    end
  end
  return formatters
end
```

Then update the Go formatter entry to use a chain:

```lua
-- In go.lua, replace the formatter section with:
formatter = {
  tool = "goimports",        -- primary (for mason install)
  chain = { "goimports", "gofumpt" }, -- run in order
  format_on_save = true,
},
```

This produces the conform config:

```lua
-- Resulting conform.nvim config for Go:
formatters_by_ft = {
  go     = { "goimports", "gofumpt" },
  gomod  = { "goimports", "gofumpt" },
  gowork = { "goimports", "gofumpt" },
  gosum  = { "goimports", "gofumpt" },
}
```

## Workflow Examples

### Workflow: Develop a new feature

```
1. Open .go file
   → gopls starts, provides completion and diagnostics
   → inlay hints show types and parameter names
   → codelens shows "run test" above test functions

2. Write a struct
   → <leader>rs     → add json tags automatically
   → <leader>rf     → fill struct with zero values

3. Define an interface
   → <leader>ri     → generate implementation stubs

4. Write code
   → <leader>re     → insert if err != nil block
   → completion shows function signatures with placeholders

5. Generate tests
   → <leader>ra     → generate table-driven test for current function
   → <leader>tt     → run the test
   → <leader>rp     → switch between impl and test file

6. Format on save → goimports + gofumpt run automatically
```

### Workflow: Debug a Go program

```
1. <leader>db     → set breakpoint
2. <leader>dc     → continue (starts debug session)
   → select "Debug file" or "Debug package"
   → delve starts, DAP UI opens
3. <F10>/<F11>    → step over/into
4. <leader>de     → eval expression
5. <leader>dt     → terminate

Alternative: debug a specific test
1. <leader>db     → set breakpoint in test
```
