# Anvil — Language Pack: TypeScript / JavaScript

Complete language support for TypeScript, JavaScript, React (TSX/JSX),
and the frontend ecosystem (HTML, CSS, Tailwind, JSON, YAML).

This document defines multiple language packs that work together:

| Pack | File | Filetypes |
|---|---|---|
| TypeScript | `lang/typescript.lua` | `typescript`, `typescriptreact`, `javascript`, `javascriptreact` |
| HTML/CSS | `lang/html.lua` | `html`, `css`, `scss`, `less`, `vue`, `svelte`, `astro` |
| JSON/YAML | `lang/json.lua` | `json`, `jsonc`, `yaml` |
| Markdown | `lang/markdown.lua` | `markdown`, `mdx` |

## Architecture Decision: typescript-tools vs vtsls

Both `typescript-tools.nvim` and `vtsls` provide TypeScript LSP.
**We use `typescript-tools.nvim`** because:

- Exposes TS-specific commands (organize imports, rename file, go to source definition)
- Filters useless diagnostics (e.g., "File is a CommonJS module")
- Better integration with Neovim (native Lua, not a separate binary)
- Actively maintained

> **Important:** Do NOT enable both. If using `astrocommunity.pack.typescript-all-in-one`,
> it may install its own TS LSP. Override it or don't import it.

## DAP Setup for JS/TS

The DAP configurations in `typescript.lua` reference `pwa-node` and `pwa-chrome`
adapters. These are registered by `nvim-dap-vscode-js` (included in the
TypeScript pack's `plugins`).

The language engine (`anvil/lang/init.lua`) collects DAP configurations from
all enabled packs and passes them to nvim-dap. The TypeScript pack's DAP
section covers:

## Post-Install Checklist

```bash
# 1. Open a .tsx file
av src/App.tsx

# 2. Check LSP is running
:LspInfo
# Should show: typescript-tools (or tsserver via typescript-tools)
# Should NOT show: vtsls AND typescript-tools simultaneously

# 3. Test Go to Definition
# Hover on imported function → gd

# 4. Test Hover
# Hover on variable → K

# 5. Test diagnostics
# Write: const x: number = "hello"
# Should see: underline + virtual text + sign column icon

# 6. Test Trouble
:Trouble diagnostics

# 7. Test formatting
# Save file → should auto-format with prettierd

# 8. Test TypeScript commands
:TSToolsOrganizeImports
:TSToolsAddMissingImports

# 9. Test Tailwind (in a Tailwind project)
# Type className=" → should show Tailwind completions

# 10. Test DAP
<leader>db   # set breakpoint
<leader>dc   # start debugging (select config)
```
