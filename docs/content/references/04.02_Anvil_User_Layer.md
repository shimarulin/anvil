# Anvil — User Layer

The user layer provides a clean separation between the base Anvil configuration (updated via `git pull`) and per-user customizations. It is loaded as Phase 6 of the boot sequence, after all core systems are ready.

## Architecture

```text
~/.config/anvil/              ← base Anvil (git repo)
│
├── lua/anvil/...             ← core (updated via git pull)
│
└── lua/user/                 ← user layer (gitignored OR separate repo)
    ├── init.lua              ← entry point: setup()
    ├── voice/
    │   └── commands.lua      ← user voice commands
    ├── keys.lua              ← keymap overrides
    ├── commands.lua          ← user text commands
    └── lang/
        └── rust.lua          ← override built-in Rust pack
```

**Key principle**: Anvil loads the user layer after its own initialization, giving it the ability to override or extend everything.

## Priority Rules

```text
User layer always wins:
  User voice commands  >  Lang pack voice commands  >  Built-in voice commands
  User keymaps         >  Built-in keymaps (same lhs replaces)
  User lang packs      >  Community lang packs      >  Built-in lang packs
```

## User Layer Files

### `lua/user/init.lua`

Entry point for the user layer. Loaded by `anvil.init` during Phase 6.

```lua
--- User customization layer for Anvil
--- This file is loaded after Anvil boot (Phase 6).
--- It is gitignored in the base Anvil repo.
--- Users maintain this directory independently.
---@class AnvilUser
local M = {}

--- Setup user customizations
--- Called by anvil.init after all core systems are ready
---@param config AnvilUserConfig the resolved Anvil config
function M.setup(config)
  -- ─── User voice commands ───
  local voice_ok, voice_commands = pcall(require, "user.voice.commands")
  if voice_ok and voice_commands.setup then
    voice_commands.setup()
  end

  -- ─── User keymaps ───
  local keys_ok, user_keys = pcall(require, "user.keys")
  if keys_ok and user_keys.overrides then
    require("anvil.core.keys").apply_overrides(user_keys.overrides)
  end

  -- ─── User text commands ───
  local cmds_ok, user_cmds = pcall(require, "user.commands")
  if cmds_ok and user_cmds.setup then
    user_cmds.setup()
  end

  -- ─── User language overrides ───
  -- Language packs in lua/user/lang/ are auto-discovered by the lang engine.
  -- No explicit setup needed here.
end

return M
```

### `lua/user/voice/commands.lua`

Example user voice commands.

```lua
--- User voice commands
--- Add your own voice commands here.
--- These have higher priority than built-in commands.
local M = {}

function M.setup()
  local commands = require("anvil.voice.commands")

  -- ─── Add new voice commands ───
  commands.register_user({
    phrases = {
      en = { "deploy staging", "ship to staging" },
      ru = { "деплой на стейджинг", "выкати на стейджинг" },
    },
    action = function()
      vim.cmd("OverseerRun deploy-staging")
    end,
    category = "custom",
    desc = "Deploy to staging",
  })

  commands.register_user({
    phrases = {
      en = { "run docker", "start containers" },
      ru = { "запусти докер", "подними контейнеры" },
    },
    action = function()
      vim.cmd("!docker-compose up -d")
    end,
    category = "custom",
    desc = "Start Docker containers",
  })

  -- ─── Override existing commands ───
  -- Change "save" to also run lint
  commands.override("Save file", {
    action = function()
      vim.cmd("write")
      vim.cmd("lua require('lint').try_lint()")
    end,
  })

  -- ─── Remove a command you don't want ───
  -- commands.remove("Toggle zen mode")
end

return M
```

### `lua/user/keys.lua`

Example user keymap overrides.

```lua
--- User keymap overrides
--- These are applied after Anvil's default keymaps.
--- Any conflicting keymap will be overridden.
local M = {}

M.overrides = {
  -- Override: use <C-s> to save
  { mode = "n", lhs = "<C-s>", rhs = "<cmd>write<CR>",
    desc = "Save file", opts = { silent = true } },
  { mode = "i", lhs = "<C-s>", rhs = "<Esc><cmd>write<CR>",
    desc = "Save file (insert mode)", opts = { silent = true } },

  -- Add: quick escape from terminal
  { mode = "t", lhs = "<Esc><Esc>", rhs = "<C-\\><C-n>",
    desc = "Exit terminal mode" },

  -- Override: different split keymaps
  { mode = "n", lhs = "<leader>sh", rhs = "<cmd>split<CR>",
    desc = "Horizontal split" },
  { mode = "n", lhs = "<leader>sv", rhs = "<cmd>vsplit<CR>",
    desc = "Vertical split" },
}

return M
```

### `lua/user/commands.lua`

Example user text commands.

```lua
--- User text commands (vim.api.nvim_create_user_command)
local M = {}

function M.setup()
  local cmd = vim.api.nvim_create_user_command

  cmd("Deploy", function(args)
    local env = args.args ~= "" and args.args or "staging"
    vim.cmd("!./scripts/deploy.sh " .. env)
  end, {
    nargs = "?",
    complete = function() return { "staging", "production", "dev" } end,
    desc = "Deploy to environment",
  })

  cmd("Scratch", function()
    vim.cmd("enew")
    vim.bo.buftype = "nofile"
    vim.bo.bufhidden = "wipe"
    vim.bo.swapfile = false
  end, { desc = "Open scratch buffer" })
end

return M
```

### `lua/user/lang/rust.lua`

Example: user override for the built-in Rust language pack.

```lua
--- User override for Rust language pack
--- Strategy: extend the built-in pack (require + modify)
--- To completely replace, just return a new AnvilLangPack table.

local base = require("anvil.lang.rust")

-- Override: disable clippy, use plain cargo check
base.lsp.settings["rust-analyzer"].check.command = "check"

-- Add custom tasks
base.tasks[#base.tasks + 1] = {
  name = "Rust: Bench",
  cmd = "cargo bench",
  lang = "rust",
  filetypes = { "rust" },
}

base.tasks[#base.tasks + 1] = {
  name = "Rust: Publish (dry-run)",
  cmd = "cargo publish --dry-run",
  lang = "rust",
  filetypes = { "rust" },
}

-- Add voice commands for Rust
base.voice_commands = {
  {
    phrases = {
      en = { "cargo build", "build rust" },
      ru = { "собери раст", "карго билд" },
    },
    action = function() vim.cmd("OverseerRun cargo build") end,
    desc = "Cargo build",
  },
  {
    phrases = {
      en = { "cargo test", "test rust" },
      ru = { "тестируй раст", "карго тест" },
    },
    action = function() vim.cmd("OverseerRun cargo test") end,
    desc = "Cargo test",
  },
}

return base
```

## .gitignore

The `lua/user/` directory is gitignored in the base Anvil repository:

```gitignore
# ─── User customization layer ───
# Users maintain lua/user/ independently (separate repo or local-only)
lua/user/
```

## User Strategies

Users can manage their layer in three ways:

### Option A — Local files (simplest)

```bash
# Just create files in lua/user/ — they are gitignored
mkdir -p ~/.config/anvil/lua/user/voice
# Edit files directly
```

### Option B — Separate git repository (recommended)

```bash
# User layer as a separate repo
git clone https://github.com/myuser/anvil-user ~/.config/anvil/lua/user

# Update Anvil:
cd ~/.config/anvil && git pull        # doesn't touch lua/user/

# Update user layer:
cd ~/.config/anvil/lua/user && git pull
```

### Option C — Git submodule

```bash
# Fork Anvil + submodule for user layer
cd ~/.config/anvil
git submodule add https://github.com/myuser/anvil-user lua/user
```

## Integration with Boot Sequence

```text
Phase 1-5: Core Anvil systems initialize
    │
    ├── Languages registered (including user/lang/ overrides)
    ├── Commands registered
    ├── "ready" event emitted
    │
Phase 6: User layer
    │
    ├── require("user").setup(config)
    │   ├── User voice commands registered (register_user)
    │   ├── User keymaps applied (apply_overrides)
    │   └── User text commands created
    │
    └── voice:initialized event (when voice first used)
        └── Lang pack voice commands registered (register_lang_commands)
```

## Health Check

The `:checkhealth anvil` command reports user layer status:

```text
Anvil User Layer
  ✓ User layer loaded (lua/user/init.lua)
  ✓ User voice commands loaded
  ✓ User keymap overrides loaded
  ℹ No user text commands (lua/user/commands.lua)
```
