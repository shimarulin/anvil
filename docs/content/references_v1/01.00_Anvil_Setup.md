# Anvil — Setup & Installation

Anvil runs as a parallel Neovim configuration alongside your existing setup.
It uses Neovim's built-in `NVIM_APPNAME` mechanism for complete isolation.

## How It Works

Neovim 0.9+ supports the `NVIM_APPNAME` environment variable, which switches
all standard paths (config, data, state, cache) to a named subdirectory:

| Path | Default (`nvim`) | Anvil (`anvil`) |
|---|---|---|
| Config | `~/.config/nvim` | `~/.config/anvil` |
| Data | `~/.local/share/nvim` | `~/.local/share/anvil` |
| State | `~/.local/state/nvim` | `~/.local/state/anvil` |
| Cache | `~/.cache/nvim` | `~/.cache/anvil` |

Everything is fully isolated — plugins, LSP servers, history, undo files.

## Directory Structure

```
~/.config/
├── nvim/                     # your existing Neovim config (untouched)
└── anvil/                    # AstroNvim + Anvil user config
    ├── init.lua              # AstroNvim entry point
    ├── lua/
    │   ├── astronvim/        # AstroNvim core (from template)
    │   ├── anvil/            # Anvil modules (our code)
    │   │   ├── init.lua
    │   │   ├── core/
    │   │   ├── lang/
    │   │   ├── ai/
    │   │   └── ...
    │   └── plugins/          # lazy.nvim plugin specs
    │       ├── core.lua
    │       ├── ai.lua
    │       ├── lang.lua
    │       └── ...
    ├── config/               # static configs (MCP, prompts, snippets)
    ├── scripts/              # automation scripts
    └── .env                  # API keys (gitignored)

~/repos/
└── anvil/                    # git repository (optional, see Approach B)
```

## Installation

### Approach A: Direct (simple)

Clone the AstroNvim template directly and add Anvil code inside it.

```bash
# 1. Clone AstroNvim template
git clone --depth 1 https://github.com/AstroNvim/template ~/.config/anvil

# 2. Remove template's git history (we'll init our own)
rm -rf ~/.config/anvil/.git

# 3. Initialize as your own repo
cd ~/.config/anvil
git init
git add .
git commit -m "init: AstroNvim template"

# 4. Add your remote
git remote add origin git@github.com:YOUR_USER/anvil.git
```

### Approach B: Symlink (separate repo)

Keep Anvil code in a separate repository and symlink it into the AstroNvim
config directory. Useful if you want to keep AstroNvim updatable via git pull.

```bash
# 1. Clone AstroNvim template
git clone --depth 1 https://github.com/AstroNvim/template ~/.config/anvil

# 2. Clone your Anvil repo
git clone git@github.com:YOUR_USER/anvil.git ~/repos/anvil

# 3. Symlink Anvil modules into the config
# Option 1: symlink the entire lua/anvil/ directory
ln -s ~/repos/anvil/lua/anvil ~/.config/anvil/lua/anvil

# Option 2: symlink plugins/ as well
ln -s ~/repos/anvil/lua/plugins ~/.config/anvil/lua/plugins

# Option 3: symlink everything except AstroNvim core
# (more complex, but gives full control)
```

> **Recommendation:** Start with Approach A. Move to Approach B later if you
> need to track AstroNvim upstream updates separately.

## Interactive Config Switcher (bonus)

A script to choose between configs using `fzf`:

```bash
# Add to ~/.bashrc or ~/.zshrc
function nvims() {
  items=("default" "anvil")
  config=$(printf "%s\n" "${items[@]}" | fzf --prompt="Neovim Config > " \
    --height=~50% --layout=reverse --border)
  if [[ -z $config ]]; then
    echo "Nothing selected"
    return 0
  elif [[ $config == "default" ]]; then
    config=""
  fi
  NVIM_APPNAME=$config nvim "$@"
}
```

```bash
nvims file.py   # shows a menu to pick config
```

## LSP Context for Config Development

When editing Anvil's own Lua files, you need LSP completions and type checking
to work correctly. This requires telling `lua_ls` where to find AstroNvim
and plugin sources.

### `.luarc.json`

Place this in the root of your Anvil repository:

```json
{
  "runtime": {
    "version": "LuaJIT",
    "path": [
      "lua/?.lua",
      "lua/?/init.lua"
    ]
  },
  "workspace": {
    "library": [
      "${VIMRUNTIME}",
      "${HOME}/.config/anvil/lua",
      "${HOME}/.local/share/anvil/lazy"
    ],
    "checkThirdParty": false
  },
  "diagnostics": {
    "globals": ["vim"]
  }
}
```

### `lazydev.nvim` (inside Neovim)

For runtime type resolution of lazy-loaded plugins, add to your plugin specs:

```lua
-- lua/plugins/core.lua (or wherever core plugins are defined)
---@type LazySpec
return {
  {
    "folke/lazydev.nvim",
    ft = "lua",
    opts = {
      library = {
        { path = "luvit-meta/library", words = { "vim%.uv" } },
        { path = vim.fn.stdpath("config") .. "/lua" },
      },
    },
  },
  { "Bilal2453/luvit-meta", lazy = true },
}
```

### Type Annotations in Code

Every plugin spec file should include type annotations:

```lua
---@type LazySpec
return {
  {
    "AstroNvim/astrocore",
    ---@type AstroCoreOpts
    opts = {
      mappings = {
        n = {
          ["<Leader>ff"] = { "<cmd>Telescope find_files<cr>", desc = "Find files" },
        },
      },
    },
  },
}
```

These annotations serve two purposes:
1. **lua_ls** uses them for autocompletion and type checking
2. **AI agents** read them as inline documentation when generating code

## AI Agent Context

AI agents (CodeCompanion, Aider, OpenCode) don't run LSP — they work with
files directly. All necessary context must exist as plain files.

### `AI_CONTEXT.md`

A universal context file readable by any AI tool. Place in the repo root:

````md
# Anvil — Project Context

## What is this

User configuration for AstroNvim v4 (Neovim). Located at `~/.config/anvil/`.
AI-native: replaces GitHub Copilot, Cline, Claude Code with open-source tools.

## Architecture

- Based on AstroNvim v4 (lazy.nvim plugin manager)
- Entry point: `init.lua` → `require("anvil").boot()`
- Plugin specs: `lua/plugins/*.lua` — each returns a LazySpec
- Anvil modules: `lua/anvil/` — core, lang, ai, editor, ui, git, workflow

## Key Modules

```lua
-- Core layer
require("anvil.core.env")      -- .env loader
require("anvil.core.events")   -- event bus
require("anvil.core.logger")   -- structured logging
require("anvil.core.cache")    -- cache with TTL

-- Language layer
require("anvil.lang")          -- language pack registry
require("anvil.lang").current() -- get pack for current filetype

-- AI layer
require("anvil.ai.providers")  -- API endpoints and models
require("anvil.ai.context")    -- context gathering
require("anvil.ai.agents")     -- CodeCompanion config
```

## Conventions

- Keymaps: via AstroCore `opts.mappings`, not `vim.keymap.set`
- Options: via AstroCore `opts.options`, not `vim.opt` directly
- Plugins: separate files in `plugins/`, each returns LazySpec
- Override built-in plugin: same name, add `opts`
- All files must have `---@type` annotations
- Code comments in English
- Documentation in Russian (English translation planned)

## Language Pack Contract

Each language is a single file in `lua/anvil/lang/` returning `AnvilLangPack`:
- `lsp` — server name and settings
- `treesitter` — parsers
- `formatter` — conform formatter
- `linter` — nvim-lint linter (nil if via LSP)
- `dap` — debug adapter
- `test` — neotest adapter
- `tasks` — overseer tasks
- `ai` — AI context (system prompt, review rules)
- `keys` — language-specific keybindings
- `plugins` — additional plugins

## Reference Files

- `.ref/astronvim-defaults.lua` — AstroNvim default configuration
- `.ref/astronvim-types.lua` — type annotations from AstroNvim plugins
- `.ref/plugins-list.txt` — installed plugins list
````

### Reference Files (`.ref/`)

Auto-generated snapshots of AstroNvim internals for AI context:

```bash
#!/bin/bash
# scripts/sync-ref.sh — update reference files for AI agents
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
REF_DIR="$SCRIPT_DIR/../.ref"
ANVIL_CONFIG="$HOME/.config/anvil"
LAZY_DIR="$HOME/.local/share/anvil/lazy"

mkdir -p "$REF_DIR"

# ─── 1. AstroNvim defaults ───
cat > "$REF_DIR/astronvim-defaults.lua" << 'HEADER'
-- AUTO-GENERATED by sync-ref.sh
-- AstroNvim default configuration snapshot
-- Do not edit manually
HEADER

for f in \
  "$ANVIL_CONFIG/lua/astronvim/init.lua" \
  "$ANVIL_CONFIG/lua/astronvim/mappings.lua" \
  "$ANVIL_CONFIG/lua/astronvim/options.lua" \
  "$ANVIL_CONFIG/lua/astronvim/autocmds.lua"; do
  if [ -f "$f" ]; then
    {
      echo ""
      echo "-- ═══════════════════════════════════════"
      echo "-- $(basename "$f")"
      echo "-- ═══════════════════════════════════════"
      cat "$f"
    } >> "$REF_DIR/astronvim-defaults.lua"
  fi
done

# ─── 2. Type annotations from key plugins ───
cat > "$REF_DIR/astronvim-types.lua" << 'HEADER'
-- AUTO-GENERATED by sync-ref.sh
-- Type annotations and function signatures from AstroNvim plugins
-- Do not edit manually
HEADER

for plugin in astrocore astrolsp astroui; do
  PLUGIN_DIR="$LAZY_DIR/$plugin"
  if [ -d "$PLUGIN_DIR" ]; then
    {
      echo ""
      echo "-- ═══════════════════════════════════════"
      echo "-- $plugin"
      echo "-- ═══════════════════════════════════════"
      grep -rn "^---@" "$PLUGIN_DIR/lua/" 2>/dev/null || true
      grep -rn "^function " "$PLUGIN_DIR/lua/" 2>/dev/null || true
    } >> "$REF_DIR/astronvim-types.lua"
  fi
done

# ─── 3. Installed plugins list ───
if [ -d "$LAZY_DIR" ]; then
  ls -1 "$LAZY_DIR/" > "$REF_DIR/plugins-list.txt" 2>/dev/null
fi

echo "Reference files updated in $REF_DIR"
```

```bash
chmod +x scripts/sync-ref.sh
./scripts/sync-ref.sh
```

### Agent-Specific Rules

#### Aider

```yaml
# .aider.conf.yml (in repo root)
read:
  - AI_CONTEXT.md
  - .ref/astronvim-defaults.lua
  - .ref/astronvim-types.lua

auto-commits: false
dark-mode: true
pretty: true
stream: true
```

#### CodeCompanion (built-in)

CodeCompanion reads context via slash commands (`/project`, `/file`, `@buffer`).

#### OpenCode

OpenCode reads files directly. Point it to `AI_CONTEXT.md`:

```bash
# In OpenCode session:
# > read AI_CONTEXT.md
```

## Updating AstroNvim

### For Approach A (direct)

AstroNvim template updates are merged manually:

```bash
cd ~/.config/anvil

# Add AstroNvim template as upstream
git remote add template https://github.com/AstroNvim/template.git

# Fetch and merge (resolve conflicts manually)
git fetch template
git merge template/main --allow-unrelated-histories
```

### For Approach B (symlink)

```bash
cd ~/.config/anvil
git pull   # updates AstroNvim template

# Sync plugins
av --headless "+Lazy! sync" +qa

# Update reference files
~/repos/anvil/scripts/sync-ref.sh
```

### Post-Update Checklist

```bash
# 1. Sync plugins
av --headless "+Lazy! sync" +qa

# 2. Update treesitter parsers
av -c "TSUpdate" -c "qa"

# 3. Update Mason tools
av -c "MasonUpdate" -c "qa"

# 4. Regenerate reference files
./scripts/sync-ref.sh

# 5. Health check
av -c "checkhealth anvil"
```

## Full Setup Script

```bash
#!/bin/bash
# scripts/install.sh — complete Anvil installation
set -euo pipefail

ANVIL_CONFIG="$HOME/.config/anvil"
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
REPO_DIR="$(cd "$SCRIPT_DIR/.." && pwd)"

echo "═══ Anvil Installation ═══"

# ─── 1. Check prerequisites ───
echo "→ Checking prerequisites..."

check_cmd() {
  if ! command -v "$1" &>/dev/null; then
    echo "ERROR: $1 is required but not installed"
    exit 1
  fi
}

check_cmd nvim
check_cmd git
check_cmd node
check_cmd npm

# Check Neovim version (need 0.9+)
NVIM_VERSION=$(nvim --version | head -1 | grep -oP '\d+\.\d+')
echo "  Neovim version: $NVIM_VERSION"

# ─── 2. Clone AstroNvim template (if not exists) ───
if [ ! -d "$ANVIL_CONFIG" ]; then
  echo "→ Cloning AstroNvim template..."
  git clone --depth 1 https://github.com/AstroNvim/template "$ANVIL_CONFIG"
  rm -rf "$ANVIL_CONFIG/.git"
else
  echo "→ Anvil config directory already exists"
fi

# ─── 3. Link Anvil modules ───
echo "→ Linking Anvil modules..."

# Link lua/anvil/
if [ -L "$ANVIL_CONFIG/lua/anvil" ]; then
  echo "  lua/anvil/ symlink already exists"
elif [ -d "$ANVIL_CONFIG/lua/anvil" ]; then
  echo "  WARNING: lua/anvil/ exists and is not a symlink"
  echo "  Backing up to lua/anvil.bak/"
  mv "$ANVIL_CONFIG/lua/anvil" "$ANVIL_CONFIG/lua/anvil.bak"
  ln -s "$REPO_DIR/lua/anvil" "$ANVIL_CONFIG/lua/anvil"
else
  ln -s "$REPO_DIR/lua/anvil" "$ANVIL_CONFIG/lua/anvil"
fi

# Link lua/plugins/
if [ -L "$ANVIL_CONFIG/lua/plugins" ]; then
  echo "  lua/plugins/ symlink already exists"
elif [ -d "$ANVIL_CONFIG/lua/plugins" ]; then
  echo "  Merging with existing plugins/"
  # Don't replace — AstroNvim template may have its own plugins
  for f in "$REPO_DIR/lua/plugins/"*.lua; do
    fname=$(basename "$f")
    ln -sf "$f" "$ANVIL_CONFIG/lua/plugins/$fname"
    echo "  Linked plugins/$fname"
  done
else
  ln -s "$REPO_DIR/lua/plugins" "$ANVIL_CONFIG/lua/plugins"
fi

# Link config/
if [ -d "$REPO_DIR/config" ]; then
  ln -sf "$REPO_DIR/config" "$ANVIL_CONFIG/config"
fi

# ─── 4. Shell alias ───
SHELL_RC="$HOME/.bashrc"
[ -n "${ZSH_VERSION:-}" ] && SHELL_RC="$HOME/.zshrc"
[ -f "$HOME/.config/fish/config.fish" ] && SHELL_RC="$HOME/.config/fish/config.fish"

if ! grep -q 'NVIM_APPNAME=anvil' "$SHELL_RC" 2>/dev/null; then
  echo "" >> "$SHELL_RC"
  echo "# Anvil (AstroNvim)" >> "$SHELL_RC"
  echo "alias av='NVIM_APPNAME=anvil nvim'" >> "$SHELL_RC"
  echo "→ Alias 'av' added to $SHELL_RC"
else
  echo "→ Alias already exists in $SHELL_RC"
fi

# ─── 5. Create .env from example ───
if [ ! -f "$REPO_DIR/.env" ] && [ -f "$REPO_DIR/.env.example" ]; then
  cp "$REPO_DIR/.env.example" "$REPO_DIR/.env"
  echo "→ Created .env from .env.example — edit it to add API keys"
fi

# ─── 6. Create MCP config directory ───
mkdir -p "$HOME/.config/anvil"
if [ -f "$REPO_DIR/config/mcp-servers.json" ] && \
   [ ! -f "$HOME/.config/anvil/mcp-servers.json" ]; then
  cp "$REPO_DIR/config/mcp-servers.json" "$HOME/.config/anvil/mcp-servers.json"
  echo "→ MCP servers config created"
fi

# ─── 7. Install plugins ───
echo "→ Installing plugins (this may take a minute)..."
NVIM_APPNAME=anvil nvim --headless "+Lazy! sync" +qa 2>/dev/null || true

# ─── 8. Generate reference files ───
echo "→ Generating reference files..."
if [ -x "$REPO_DIR/scripts/sync-ref.sh" ]; then
  "$REPO_DIR/scripts/sync-ref.sh"
fi

echo ""
echo "═══ Installation complete ═══"
echo ""
echo "Next steps:"
echo "  1. Edit .env to add your AI API keys"
echo "  2. Source your shell: source $SHELL_RC"
echo "  3. Launch: av"
echo "  4. Inside Neovim: :checkhealth anvil"
echo "  5. Index your first project: :AnvilIndex"
```

```bash
chmod +x scripts/install.sh
```

## Compatibility Matrix

How different tools access Anvil's context:

| Mechanism | lua_ls | CodeCompanion | Aider | OpenCode |
|---|---|---|---|---|
| `.luarc.json` | ✅ | — | — | — |
| `lazydev.nvim` | ✅ | — | — | — |
| `---@type` annotations | ✅ | ✅* | ✅* | ✅* |
| `AI_CONTEXT.md` | — | via `/project` | ✅ (auto-read) | ✅ (manual) |
| `.ref/` reference files | — | via `/file` | ✅ (auto-read) | ✅ (manual) |
| `.aider.conf.yml` | — | — | ✅ | — |
| Slash commands (`/project`) | — | ✅ | — | — |
| MCP servers | — | ✅ | — | — |

\* AI agents read annotations as part of source code and use them as hints,
but do not perform type checking.
