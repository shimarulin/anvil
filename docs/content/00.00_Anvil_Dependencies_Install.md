## Quick Start

```bash
chmod +x preinstall.sh
./preinstall.sh
```

After the script finishes:

1. **Restart your terminal** (so font caches and PATH changes take effect).
2. **Set your terminal font** to `JetBrainsMono Nerd Font` (not the Mono variant).
3. Open Neovim and run `:checkhealth provider` to confirm everything works.

## Architecture & Design Decisions

### OS Detection & Package Managers

The script detects the OS via `uname -s` and then probes for known package managers in order. Each install function uses a `case` statement to dispatch the correct command:

```bash
case "$PKG" in
    apt)     sudo apt-get install -y "$p" ;;
    brew)    brew install "$p" ;;
    pacman)  sudo pacman -S --needed --noconfirm "$p" ;;
    # ...
esac
```

For packages whose names differ across distributions (e.g. `build-essential` on Debian vs `base-devel` on Arch), the `MAPPED_PACKAGES` array uses a pipe-delimited format:

```bash
# Format: "apt|brew|pacman|dnf"
MAPPED_PACKAGES=(
    "build-essential|gcc|base-devel|gcc"
    "fd-find|fd|fd|fd-find"
)
```

Use `"-"` to fall back to the apt name for a given manager.

### Neovim Version Guarantee

Neovim ≥ 0.11 is required (AstroNvim v5 requires 0.10+, and 0.11 enables additional features). Many distribution repositories ship older versions (especially `apt` on Ubuntu LTS). The script handles this:

```
Install via package manager
        │
        ▼
  Check version ≥ 0.11?
  ┌─────┴─────┐
  │ YES       │ NO
  │ Done      │ Download latest release
  │           │ from GitHub (prebuilt tarball)
  │           │ Install to /opt/nvim
  │           │ Symlink to /usr/local/bin/nvim
  └───────────┘
```

On `apt`-based systems the script skips the package manager entirely and goes straight to the GitHub release, because the repository version is almost always too old.

The GitHub release tag is fetched dynamically via the API so the script always gets the latest stable version:

```bash
tag="$(curl -fsSL https://api.github.com/repos/neovim/neovim/releases/latest \
       | grep '"tag_name"' | head -1 | cut -d'"' -f4)"
```

### Nerd Font Selection

The script installs **JetBrainsMono Nerd Font** from the `ryanoasis/nerd-fonts` releases.

**Important:** The terminal font must be set to `JetBrainsMono Nerd Font`, **not** `JetBrainsMono Nerd Font Mono`. The Mono variant constrains icon glyphs to a single character cell, making them noticeably smaller.

The font files are placed in:

| OS | Directory |
|---|---|
| macOS | `~/Library/Fonts/` |
| Linux | `~/.local/share/fonts/` |

On Linux the font cache is refreshed automatically via `fc-cache`.

The script checks for existing font files before downloading to avoid redundant work on repeated runs.

### Clipboard Tool

Neovim requires a clipboard tool for system clipboard integration (see `:help clipboard-tool`). Without one, `"+y` and `"+p` (yank/paste to system clipboard) will not work.

| Platform | Tool | Notes |
|---|---|---|
| macOS | `pbcopy` / `pbpaste` | Built-in, nothing to install |
| Linux (X11) | `xclip` or `xsel` | Script installs `xclip` by default |
| Linux (Wayland) | `wl-clipboard` (`wl-copy` / `wl-paste`) | Script detects `$WAYLAND_DISPLAY` |

The script detects the display server by checking the `$WAYLAND_DISPLAY` environment variable:

- If set → installs `wl-clipboard`
- Otherwise → installs `xclip`

If any clipboard tool is already present (`xclip`, `xsel`, or `wl-copy`), installation is skipped.

### Python Packages & PEP 668

[PEP 668](https://peps.python.org/pep-0668/) marks system Python
installations as "externally managed", preventing `pip install` from
modifying them. This is enforced by default on:

- **Arch Linux** (always)
- **macOS Homebrew Python** (always)
- **Ubuntu ≥ 23.04**, **Fedora ≥ 38**, and others (when the
  `EXTERNALLY-MANAGED` marker file is present)

Running `pip install pynvim` on these systems produces:

```
error: externally-managed-environment
```

**Our solution:** The script creates a dedicated Python virtual environment and installs packages there:

```
~/.local/share/nvim-deps-venv/
├── bin/
│   ├── python3       ← isolated Python
│   ├── pip           ← isolated pip
│   └── ...           ← package binaries
└── lib/
    └── python3.x/
        └── site-packages/
            └── pynvim/
```

Any binaries installed by pip packages are symlinked into `~/.local/bin/` so they are available in `$PATH` (generic names like `python3`, `pip`, `activate` are excluded to avoid shadowing system binaries).

Detection logic:

```bash
is_externally_managed() {
    [[ "$PKG" == "pacman" ]] && return 0   # Arch: always
    [[ "$PKG" == "brew" ]]   && return 0   # Homebrew: always
    # Others: check for the marker file
    local stdlib
    stdlib="$(python3 -c 'import sysconfig; print(sysconfig.get_path("stdlib"))')"
    [[ -f "${stdlib}/EXTERNALLY-MANAGED" ]] && return 0
    return 1
}
```

### Global Neovim Plugin for Python Provider

Neovim needs to know which `python3` binary has `pynvim` installed. Normally you would set `vim.g.python3_host_prog` in your `init.lua`. But when multiple Neovim configurations are used (NvChad, AstroNvim, LazyVim, kickstart, custom, `NVIM_APPNAME`-based setups), editing each one is impractical.

**Solution:** The script creates a **global plugin file** that Neovim loads automatically, regardless of which configuration is active.

#### How it works

Neovim always includes `~/.local/share/nvim/site/` in its `runtimepath`. Any `.lua` file in the `plugin/` subdirectory is sourced on startup, **before** the user's `init.lua`.

The script creates:

```
~/.local/share/nvim/site/plugin/python3_host.lua
```

With the following content:

```lua
-- Auto-generated by preinstall.sh
-- Points Neovim Python 3 provider to the venv with pynvim.
-- Applies to ALL Neovim configs (NvChad, AstroNvim, LazyVim, kickstart, custom, etc.)
-- Any config can override by setting vim.g.python3_host_prog itself.
-- To undo: delete this file.
if not vim.g.python3_host_prog then
  vim.g.python3_host_prog = "/home/user/.local/share/nvim-deps-venv/bin/python3"
end
```

#### Load order

```
Neovim starts
│
├── 1. Loads ~/.local/share/nvim/site/plugin/*.lua   ← global plugins
│      └── python3_host.lua sets python3_host_prog
│          ONLY if it hasn't been set already
│
├── 2. Loads ~/.config/nvim/init.lua                  ← user config
│      └── can override python3_host_prog if needed
│
└── Result: pynvim works out of the box for every config
```

#### Why `if not vim.g.python3_host_prog`?

This guard ensures the global plugin is a **default**, not a mandate. If any Neovim configuration explicitly sets `python3_host_prog`, that value takes priority. The global plugin only fills in the blank.

#### Compatibility matrix

| Scenario | Works? | Notes |
|---|---|---|
| NvChad | ✅ | No config changes needed |
| AstroNvim v5 | ✅ | No config changes needed |
| LazyVim | ✅ | No config changes needed |
| kickstart.nvim | ✅ | No config changes needed |
| Custom config | ✅ | No config changes needed |
| `NVIM_APPNAME=foo nvim` | ✅ | `site/plugin/` is shared across all app names |
| Config sets its own `python3_host_prog` | ✅ | Config value wins (guard prevents overwrite) |

### PATH Configuration & zsh Considerations

Several tools are installed into `~/.local/bin/`:

- Python package binaries (symlinked from the venv)
- Potentially `tree-sitter` and other npm globals (depending on npm prefix)

The script checks whether `~/.local/bin` is already in `$PATH`. If not, it prompts the user interactively:

```
[WARN] $HOME/.local/bin is NOT in your $PATH
[INFO] Some installed tools (tree-sitter, Python packages) live there.

  Add export PATH="$HOME/.local/bin:$PATH"
  to /Users/you/.zshenv? [y/N]
```

#### Why `~/.zshenv` specifically (not `~/.zshrc` or `$ZDOTDIR/.zshenv`)?

zsh loads configuration files in this order:

```
~/.zshenv → $ZDOTDIR/.zshrc → $ZDOTDIR/.zprofile → $ZDOTDIR/.zlogin
```

The critical detail: **zsh hardcodes `~/.zshenv` as the first file it reads.** The `$ZDOTDIR` variable only takes effect *after* `~/.zshenv` has been sourced. This means:

| File | Read by zsh? | When |
|---|---|---|
| `~/.zshenv` | ✅ Always | First, before anything else |
| `$ZDOTDIR/.zshenv` | ❌ Never | zsh does NOT re-read `.zshenv` from `$ZDOTDIR` |
| `$ZDOTDIR/.zshrc` | ✅ Interactive only | After `~/.zshenv` sets `$ZDOTDIR` |
| `~/.zshrc` | Only if `$ZDOTDIR` is unset | Falls back to `$HOME` |

This is a common source of confusion. If your zsh config lives in `~/.config/zsh/` (via `ZDOTDIR`), you might expect `~/.config/zsh/.zshenv` to be loaded — but it is not. Only `~/.zshenv` is read at startup.

That's why the script **always writes to `~/.zshenv`**, regardless of `$ZDOTDIR`. This ensures PATH is available in:

- Interactive shells
- Non-interactive shells (scripts)
- Neovim's `:!command` and `vim.fn.system()`
- Subprocesses spawned by any tool

#### Why not `.zshrc`?

`.zshrc` is only loaded for interactive shells. If PATH is set there, tools won't be found when:

- Neovim runs shell commands internally
- Scripts are executed non-interactively
- Cron jobs or other automation runs

#### Shell detection summary

| Shell | Config file | Export syntax |
|---|---|---|
| zsh | `~/.zshenv` | `export PATH="$HOME/.local/bin:$PATH"` |
| bash (Linux) | `~/.bashrc` | `export PATH="$HOME/.local/bin:$PATH"` |
| bash (macOS) | `~/.bash_profile` | `export PATH="$HOME/.local/bin:$PATH"` |
| fish | `~/.config/fish/config.fish` | `fish_add_path "$HOME/.local/bin"` |

The script will:

1. Skip if `~/.local/bin` is already in `$PATH`
2. Skip if the export line is already in the config file (avoids duplicates)
3. Create the config file if it doesn't exist yet
4. Ask before modifying anything (user can decline)
5. Export for the current session immediately after adding

### Homebrew Dead Taps

Homebrew occasionally deprecates taps (e.g. `homebrew/cask-fonts` was merged into `homebrew/cask`). If these stale taps remain configured, `brew update` prints errors like:

```
Error: homebrew/homebrew-cask-fonts does not exist!
```

The script detects and removes dead taps before running `brew update`:

```bash
local dead_taps
dead_taps="$(brew tap 2>/dev/null | grep -E 'cask-fonts|cask-drivers' || true)"
for tap in $dead_taps; do
    brew untap "$tap" 2>/dev/null || true
done
```

### Optional AstroNvim Tools

AstroNvim v5 provides built-in terminal toggle mappings for several tools. These are optional but recommended for the full AstroNvim experience:

| Tool | AstroNvim Mapping | Purpose | Installation |
|---|---|---|---|
| **lazygit** | `<Leader>gg`, `<Leader>tl` | Git TUI | Package manager or GitHub release |
| **gdu** | `<Leader>tu` | Disk usage analyzer | Package manager or GitHub release |
| **bottom** (`btm`) | `<Leader>tt` | Process viewer | Package manager or GitHub release |

On distributions where these tools are not available in the default repositories (notably `apt`-based systems), the script downloads prebuilt binaries from GitHub releases and installs them to `/usr/local/bin/`.

These tools are installed in a separate `install_optional_packages` step and their absence does **not** cause the verification to fail — they are reported as warnings only.

## Adding New Dependencies

All dependencies are defined in arrays at the top of `preinstall.sh`. To add a new package, append it to the appropriate array — no other code changes required.

### System packages

```bash
SYSTEM_PACKAGES=(
    git curl wget unzip make ripgrep
    fd        # ← add here
)
```

If the package binary name differs from the package name, add a mapping to the `pkg_bin` function:

```bash
pkg_bin() {
    case "$1" in
        ripgrep)  echo "rg" ;;
        fd-find)  echo "fd" ;;   # ← add here
        *)        echo "$1" ;;
    esac
}
```

### Packages with different names across distros

```bash
# Format: "apt|brew|pacman|dnf"
MAPPED_PACKAGES=(
    "build-essential|gcc|base-devel|gcc"
    "fd-find|fd|fd|fd-find"              # ← add here
)
```

### npm packages

```bash
NPM_PACKAGES=(
    tree-sitter-cli
    neovim        # ← uncomment or add
    typescript    # ← add here
    prettier      # ← add here
)
```

### Python packages

```bash
PIP_PACKAGES=(
    pynvim
    black         # ← add here
    ruff          # ← add here
    debugpy       # ← add here
)
```

## Verifying the Installation

### From the command line

Run the script again — it will skip already-installed packages and show a verification summary at the end.

Or check manually:

```bash
nvim --version | head -1       # NVIM v0.11.x
node --version                 # v2x.x.x
npm --version                  # 10.x.x
tree-sitter --version          # tree-sitter x.x.x
rg --version                   # ripgrep x.x.x
fd --version                   # fd x.x.x
python3 --version              # Python 3.x.x
lazygit --version              # lazygit version=x.x.x
gdu --version                  # gdu x.x.x
btm --version                  # btm x.x.x
```

Check clipboard:

```bash
# Linux X11
echo "test" | xclip -selection clipboard && xclip -selection clipboard -o

# Linux Wayland
echo "test" | wl-copy && wl-paste

# macOS
echo "test" | pbcopy && pbpaste
```

### From inside Neovim

```vim
:checkhealth provider
```

Expected output for the Python section:

```
Python 3 provider (optional) ~
- ✅ OK Using: /home/user/.local/share/nvim-deps-venv/bin/python3
- ✅ OK pynvim version: 0.6.0

Python virtualenv ~
- ✅ OK no $VIRTUAL_ENV
```

Check clipboard inside Neovim:

```vim
:checkhealth provider
```

Look for the **Clipboard** section — it should show the detected tool.

If you see warnings instead, check:

1. The global plugin file exists:
   ```bash
   cat ~/.local/share/nvim/site/plugin/python3_host.lua
   ```

2. The venv Python can import pynvim:
   ```bash
   ~/.local/share/nvim-deps-venv/bin/python3 -c "import pynvim; print('OK')"
   ```

### Tree-sitter parsers

After opening Neovim with a config that includes `nvim-treesitter`:

```vim
:TSInstall lua python javascript
:TSInstallInfo
```

If parsers fail to compile, ensure `gcc`/`make` are installed (the script handles this, but verify with `gcc --version` and `make --version`).

## Uninstalling / Reverting

| Component | How to remove |
|---|---|
| Global Python plugin | `rm ~/.local/share/nvim/site/plugin/python3_host.lua` |
| Python venv | `rm -rf ~/.local/share/nvim-deps-venv` |
| Symlinks in `~/.local/bin` | Remove any symlinks pointing into the venv |
| PATH line in shell config | Remove the `# Added by Neovim install script` block from `~/.zshenv` / `.bashrc` etc. |
| Nerd Font (macOS) | Delete `*JetBrainsMono*` files from `~/Library/Fonts/` |
| Nerd Font (Linux) | Delete `*JetBrainsMono*` files from `~/.local/share/fonts/` |
| Neovim (GitHub install) | `sudo rm -rf /opt/nvim /usr/local/bin/nvim` |
| Neovim (package manager) | Use `brew uninstall neovim`, `sudo apt remove neovim`, etc. |
| npm packages | `npm uninstall -g tree-sitter-cli` |
| lazygit (GitHub install) | `sudo rm /usr/local/bin/lazygit` |
| gdu (GitHub install) | `sudo rm /usr/local/bin/gdu` |
| bottom (GitHub install) | `sudo rm /usr/local/bin/btm` |
| System packages | Remove via your package manager |

## Troubleshooting

### `error: externally-managed-environment` when running `pip install` manually

This is expected. The system Python is protected by PEP 668. The install script already handles this by using a dedicated virtual environment. Do not run `pip install` against the system Python — use the venv instead:

```bash
~/.local/share/nvim-deps-venv/bin/pip install <package>
```

### `homebrew/homebrew-cask-fonts does not exist`

The script auto-removes this dead tap. If you see this error outside the script, run:

```bash
brew untap homebrew/cask-fonts
```

### Neovim version is too old after install

On `apt`-based systems the repository version is often outdated. The script falls back to the GitHub release automatically. If you installed Neovim through another method, remove it first and re-run the script.

### Icons look small in Neovim

You are using the **Mono** variant of the Nerd Font. Change your terminal font to `JetBrainsMono Nerd Font` (without `Mono` at the end).

### `tree-sitter` or other tools not found after install

Ensure `~/.local/bin` is in your `$PATH`. The script offers to add it automatically during installation. If you declined, add manually:

```bash
# zsh — add to ~/.zshenv (NOT .zshrc, NOT $ZDOTDIR/.zshenv)
export PATH="$HOME/.local/bin:$PATH"

# bash
export PATH="$HOME/.local/bin:$PATH"

# fish
fish_add_path "$HOME/.local/bin"
```

Then restart your terminal or run `source ~/.zshenv`.

### Why `~/.zshenv` and not `$ZDOTDIR/.zshenv`?

zsh only reads `.zshenv` from `$HOME`. The `$ZDOTDIR` variable redirects where zsh looks for `.zshrc`, `.zprofile`, and `.zlogin` — but **not** `.zshenv`. This is hardcoded in zsh itself. A file at `$ZDOTDIR/.zshenv` is never loaded automatically.

Reference: `man zshall` → section "STARTUP/SHUTDOWN FILES".

### `:checkhealth provider` still shows Python warnings

1. Verify the global plugin exists and points to the correct path:
   ```bash
   cat ~/.local/share/nvim/site/plugin/python3_host.lua
   ```

2. Verify pynvim is importable:
   ```bash
   ~/.local/share/nvim-deps-venv/bin/python3 -c "import pynvim; print('OK')"
   ```

3. Make sure no other config is setting `python3_host_prog` to a different (broken) path. Search your config:
   ```bash
   grep -r "python3_host_prog" ~/.config/nvim/
   ```

### Clipboard not working in Neovim

1. Check `:checkhealth provider` for the Clipboard section
2. On Linux, ensure you have the right tool for your display server:
   - X11: `xclip` or `xsel`
   - Wayland: `wl-clipboard` (`wl-copy` / `wl-paste`)
3. In a headless/SSH session without a display server, clipboard integration requires additional setup (e.g. OSC 52 support in your terminal)

### lazygit / gdu / bottom not found

These are optional tools. On `apt`-based systems they are installed from GitHub releases to `/usr/local/bin/`. If installation failed:

1. Check if `/usr/local/bin` is in your `$PATH`
2. Try installing manually from the respective GitHub releases pages
3. These tools are not required — AstroNvim will simply show an error when you try to use the corresponding mapping
