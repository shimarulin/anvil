# Installation Guide

This document describes the automated setup script (`install.sh`) for the
Neovim development environment. It covers what gets installed, why certain
decisions were made, and how to maintain the script going forward.

## Quick Start

```bash
chmod +x install.sh
./install.sh
```

After the script finishes:

1. **Restart your terminal** (so font caches and PATH changes take effect).
2. **Set your terminal font** to `JetBrainsMono Nerd Font` (not the `Mono` variant).
3. Open Neovim and run `:checkhealth provider` to confirm everything works.

## What Gets Installed

| Component | Purpose |
|---|---|
| **Neovim** (latest, ≥ 0.11) | The editor itself |
| **JetBrainsMono Nerd Font** | Terminal font with icon glyphs for UI plugins |
| **git, curl, wget, unzip, make, gcc** | Build tools required by plugins and tree-sitter |
| **ripgrep** (`rg`) | Fast grep — used by Telescope for live search (optional but recommended) |
| **Node.js + npm** | Runtime for tree-sitter-cli and other JS-based tools |
| **tree-sitter-cli** | Builds tree-sitter parsers used by `nvim-treesitter` |
| **Python 3 + pynvim** | Python provider for Neovim (required by some plugins) |
| **Global Neovim plugin** | Auto-configures the Python provider for all Neovim configs |

## Architecture & Design Decisions

### OS Detection & Package Managers

The script detects the OS via `uname -s` and then probes for known package
managers in order. Each install function uses a `case` statement to dispatch
the correct command:

```bash
case "$PKG" in
    apt)    sudo apt-get install -y "$p" ;;
    brew)   brew install "$p" ;;
    pacman) sudo pacman -S --needed --noconfirm "$p" ;;
    # ...
esac
```

For packages whose names differ across distributions (e.g. `build-essential`
on Debian vs `base-devel` on Arch), the `MAPPED_PACKAGES` array uses a
pipe-delimited format:

```bash
# Format: "apt|brew|pacman|dnf"
MAPPED_PACKAGES=(
    "build-essential|gcc|base-devel|gcc"
)
```

Use `"-"` to fall back to the apt name for a given manager.

---

### Neovim Version Guarantee

Neovim ≥ 0.11 is required. Many distribution repositories ship older versions
(especially `apt` on Ubuntu LTS). The script handles this:

```
Install via package manager
        │
        ▼
  Check version ≥ 0.11?
   ┌─────┴─────┐
   │ YES        │ NO
   │ Done       │ Download latest release
   │            │ from GitHub (prebuilt tarball)
   │            │ Install to /opt/nvim
   │            │ Symlink to /usr/local/bin/nvim
   └────────────┘
```

On `apt`-based systems the script skips the package manager entirely and goes
straight to the GitHub release, because the repository version is almost
always too old.

The GitHub release tag is fetched dynamically via the API so the script
always gets the latest stable version:

```bash
tag="$(curl -fsSL https://api.github.com/repos/neovim/neovim/releases/latest \
       | grep '"tag_name"' | head -1 | cut -d'"' -f4)"
```

### Nerd Font Selection

The script installs **JetBrainsMono Nerd Font** from the
[ryanoasis/nerd-fonts](https://github.com/ryanoasis/nerd-fonts) releases.

> **Important:** The terminal font must be set to `JetBrainsMono Nerd Font`,
> **not** `JetBrainsMono Nerd Font Mono`. The `Mono` variant constrains icon
> glyphs to a single character cell, making them noticeably smaller.

The font files are placed in:

| OS | Directory |
|---|---|
| macOS | `~/Library/Fonts/` |
| Linux | `~/.local/share/fonts/` |

On Linux the font cache is refreshed automatically via `fc-cache`.

The script checks for existing font files before downloading to avoid
redundant work on repeated runs.

### Python Packages & PEP 668

[PEP 668](https://peps.python.org/pep-0668/) marks system Python
installations as "externally managed", preventing `pip install` from
modifying them. This is enforced by default on:

- **Arch Linux** (always)
- **macOS Homebrew Python** (always)
- **Ubuntu ≥ 23.04**, **Fedora ≥ 38**, and others (when the
  `EXTERNALLY-MANAGED` marker file is present)

Running `pip install pynvim` on these systems produces:

```
error: externally-managed-environment
```

**Our solution:** The script creates a dedicated Python virtual environment
and installs packages there:

```
~/.local/share/nvim-deps-venv/
├── bin/
│   ├── python3       ← isolated Python
│   ├── pip           ← isolated pip
│   └── ...           ← package binaries
└── lib/
    └── python3.x/
        └── site-packages/
            └── pynvim/
```

Any binaries installed by pip packages are symlinked into `~/.local/bin/`
so they are available in `$PATH` (generic names like `python3`, `pip`,
`activate` are excluded to avoid shadowing system binaries).

Detection logic:

```bash
is_externally_managed() {
    [[ "$PKG" == "pacman" ]] && return 0    # Arch: always
    [[ "$PKG" == "brew" ]]   && return 0    # Homebrew: always
    # Others: check for the marker file
    local stdlib
    stdlib="$(python3 -c 'import sysconfig; print(sysconfig.get_path("stdlib"))')"
    [[ -f "${stdlib}/EXTERNALLY-MANAGED" ]] && return 0
    return 1
}
```

### Global Neovim Plugin for Python Provider

Neovim needs to know which `python3` binary has `pynvim` installed. Normally
you would set `vim.g.python3_host_prog` in your `init.lua`. But when
multiple Neovim configurations are used (NvChad, LazyVim, kickstart, custom,
`NVIM_APPNAME`-based setups), editing each one is impractical.

**Solution:** The script creates a global plugin file that Neovim loads
automatically, regardless of which configuration is active.

#### How it works

Neovim always includes `~/.local/share/nvim/site/` in its `runtimepath`.
Any `.lua` file in the `plugin/` subdirectory is sourced on startup, before
the user's `init.lua`.

The script creates:

```
~/.local/share/nvim/site/plugin/python3_host.lua
```

With the following content:

```lua
-- Auto-generated by install.sh
-- Points Neovim Python 3 provider to the venv with pynvim.
-- Applies to ALL Neovim configs (NvChad, LazyVim, kickstart, custom, etc.)
-- Any config can override by setting vim.g.python3_host_prog itself.
-- To undo: delete this file.
if not vim.g.python3_host_prog then
  vim.g.python3_host_prog = "/home/user/.local/share/nvim-deps-venv/bin/python3"
end
```

#### Load order

```
Neovim starts
│
├── 1. Loads ~/.local/share/nvim/site/plugin/*.lua     ← global plugins
│      └── python3_host.lua sets python3_host_prog
│          ONLY if it hasn't been set already
│
├── 2. Loads ~/.config/nvim/init.lua                   ← user config
│      └── can override python3_host_prog if needed
│
└── Result: pynvim works out of the box for every config
```

#### Why `if not vim.g.python3_host_prog`?

This guard ensures the global plugin is a **default, not a mandate**. If any
Neovim configuration explicitly sets `python3_host_prog`, that value takes
priority. The global plugin only fills in the blank.

#### Compatibility matrix

| Scenario | Works? | Notes |
|---|---|---|
| NvChad | ✅ | No config changes needed |
| LazyVim | ✅ | No config changes needed |
| kickstart.nvim | ✅ | No config changes needed |
| Custom config | ✅ | No config changes needed |
| `NVIM_APPNAME=foo nvim` | ✅ | `site/plugin/` is shared across all app names |
| Config sets its own `python3_host_prog` | ✅ | Config value wins (guard prevents overwrite) |

### Homebrew Dead Taps

Homebrew occasionally deprecates taps (e.g. `homebrew/cask-fonts` was merged
into `homebrew/cask`). If these stale taps remain configured, `brew update`
prints errors like:

```
Error: homebrew/homebrew-cask-fonts does not exist!
```

The script detects and removes dead taps before running `brew update`:

```bash
local dead_taps
dead_taps="$(brew tap 2>/dev/null | grep -E 'cask-fonts|cask-drivers' || true)"
for tap in $dead_taps; do
    brew untap "$tap" 2>/dev/null || true
done
```

## Adding New Dependencies

All dependencies are defined in arrays at the top of `install.sh`. To add a
new package, append it to the appropriate array — no other code changes
required.

### System packages

```bash
SYSTEM_PACKAGES=(
    git
    curl
    wget
    unzip
    make
    ripgrep
    fd              # ← add here
    lazygit         # ← add here
)
```

If the package binary name differs from the package name, add a mapping to
the `pkg_bin` function:

```bash
pkg_bin() {
    case "\$1" in
        ripgrep)  echo "rg" ;;
        fd-find)  echo "fd" ;;   # ← add here
        *)        echo "\$1" ;;
    esac
}
```

### Packages with different names across distros

```bash
# Format: "apt|brew|pacman|dnf"
MAPPED_PACKAGES=(
    "build-essential|gcc|base-devel|gcc"
    "fd-find|fd|fd|fd-find"          # ← add here
)
```

### npm packages

```bash
NPM_PACKAGES=(
    tree-sitter-cli
    neovim          # ← uncomment or add
    typescript      # ← add here
    prettier        # ← add here
)
```

### Python packages

```bash
PIP_PACKAGES=(
    pynvim
    black           # ← add here
    ruff            # ← add here
    debugpy         # ← add here
)
```

## Verifying the Installation

### From the command line

Run the script again — it will skip already-installed packages and show
a verification summary at the end.

Or check manually:

```bash
nvim --version | head -1          # NVIM v0.11.x
node --version                    # v2x.x.x
npm --version                     # 10.x.x
tree-sitter --version             # tree-sitter x.x.x
rg --version                      # ripgrep x.x.x
python3 --version                 # Python 3.x.x
```

### From inside Neovim

```vim
:checkhealth provider
```

Expected output for the Python section:

```
Python 3 provider (optional) ~
- ✅ OK Using: /home/user/.local/share/nvim-deps-venv/bin/python3
- ✅ OK pynvim version: 0.6.0

Python virtualenv ~
- ✅ OK no $VIRTUAL_ENV
```

If you see warnings instead, check:

1. The global plugin file exists:
   ```bash
   cat ~/.local/share/nvim/site/plugin/python3_host.lua
   ```
2. The venv Python can import pynvim:
   ```bash
   ~/.local/share/nvim-deps-venv/bin/python3 -c "import pynvim; print('OK')"
   ```

### Tree-sitter parsers

After opening Neovim with a config that includes `nvim-treesitter`:

```vim
:TSInstall lua python javascript
:TSInstallInfo
```

If parsers fail to compile, ensure `gcc`/`make` are installed (the script
handles this, but verify with `gcc --version` and `make --version`).

## Uninstalling / Reverting

| Component | How to remove |
|---|---|
| Global Python plugin | `rm ~/.local/share/nvim/site/plugin/python3_host.lua` |
| Python venv | `rm -rf ~/.local/share/nvim-deps-venv` |
| Symlinks in `~/.local/bin` | Remove any symlinks pointing into the venv |
| Nerd Font (macOS) | Delete `*JetBrainsMono*` files from `~/Library/Fonts/` |
| Nerd Font (Linux) | Delete `*JetBrainsMono*` files from `~/.local/share/fonts/` |
| Neovim (GitHub install) | `sudo rm -rf /opt/nvim /usr/local/bin/nvim` |
| Neovim (package manager) | Use `brew uninstall neovim`, `sudo apt remove neovim`, etc. |
| npm packages | `npm uninstall -g tree-sitter-cli` |
| System packages | Remove via your package manager |

## Troubleshooting

### `error: externally-managed-environment` when running `pip install` manually

This is expected. The system Python is protected by PEP 668. The install
script already handles this by using a dedicated virtual environment. Do not
run `pip install` against the system Python — use the venv instead:

```bash
~/.local/share/nvim-deps-venv/bin/pip install <package>
```

### `homebrew/homebrew-cask-fonts does not exist`

The script auto-removes this dead tap. If you see this error outside the
script, run:

```bash
brew untap homebrew/cask-fonts
```

### Neovim version is too old after install

On `apt`-based systems the repository version is often outdated. The script
falls back to the GitHub release automatically. If you installed Neovim
through another method, remove it first and re-run the script.

### Icons look small in Neovim

You are using the `Mono` variant of the Nerd Font. Change your terminal font
to `JetBrainsMono Nerd Font` (without `Mono` at the end).

### `tree-sitter` command not found after install

Ensure `~/.local/bin` is in your `$PATH`. Add to your shell profile:

```bash
# ~/.zshrc or ~/.bashrc
export PATH="$$HOME/.local/bin:$$PATH"
```

### `:checkhealth provider` still shows Python warnings

1. Verify the global plugin exists and points to the correct path:
   ```bash
   cat ~/.local/share/nvim/site/plugin/python3_host.lua
   ```
2. Verify pynvim is importable:
   ```bash
   ~/.local/share/nvim-deps-venv/bin/python3 -c "import pynvim; print('OK')"
   ```
3. Make sure no other config is setting `python3_host_prog` to a different
   (broken) path. Search your config:
   ```bash
   grep -r "python3_host_prog" ~/.config/nvim/
   ```
